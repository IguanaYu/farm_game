## 2. 验收对照（总计划 §10-2.6）

| 验收项 | 结果 | 证据 |
| --- | --- | --- |
| 玩家不能操作队友牌或物品 | 通过 | 客机动作按成员键路由；出牌/领取/分享均主机校验 |
| 同时出牌和同时拾取只按权威顺序结算 | 通过 | session_smoke：动作带 ID 去重、到达序执行 |
| 分享取消不丢物 | 通过 | share_accept 失败整体回滚；combat_coop/单测断言留原主 |
| 双方看到相同敌人与节点 | 通过 | 主机广播快照；客机镜像同一 run（含缩放后敌人） |
| 结算分别回正确个人档，主机不代写客户端农场档 | 通过 | 客机结算单 `guest_handoff` 只落盘；客机自行应用（d26 断言双方 applied_settlements 各自登记） |

设计 §11 合作算例的骨架（掩护支援降低风险、满包者让货、带货影响撤离决策）在规则与协议层均可复现。

## 3. 实施记录与偏差

1. **传输层为裸 ENet＋JSON 包协议**（不走 MultiplayerAPI 场景树）：可在 headless 单进程内同时驱动两端做全链路测试，也支持跨进程真实部署；代价是 UI 面板需自行轮询（已用 _process 泵）。
2. **主机个人放弃**：按"结算本人＋会话保留"记录，剩余成员继续的完整语义随 2.7 恢复扩展（设计 §10 细化）。
3. **客机界面为最小可用版**（投票/领取/撤离/放弃四类意图＋状态镜像）；战斗中客机出牌经主机界面代发或测试入口——完整并排战斗视图与快捷信号条在 2.8 打磨（原计划 §2 已预告）。
4. `get_packet_peer` 必须在 `get_packet` 前读取，否则客机会被误登记为 peer 1（实施中发现并修复）。
5. 敌人目标采用"固定指派＋倒地重选"，未做交替/群攻变体（内容里暂无对应敌人；2.8 加新敌人时按 `target_rule` 扩展）。
