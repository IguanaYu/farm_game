# Godot 单人首版开发计划 v0.1

整理日期：2026-09-28。依据[玩法循环草案](../design/Godot_多人种田偷菜_玩法循环_v0.1.md)制定。本文是实施顺序和验收清单；玩法数值以玩法文档的**较新已确认规则**为准，试玩后再调整。

**进度（2026-09-28）：**阶段 1 已做出可玩农场场景，并通过 Godot 4.6.1 导入、启动、地块点选和规则层闭环检查；[操作说明](../../README.md)与[首屏预览](../../screenshots/stage1_preview.png)已保存。阶段 2～6 待开始。外部素材盘点仍待合并到资产映射表。

## 目标与范围

先交付 Windows 上可玩的**单人、点击操作、现实时间种植**版本。玩家从六块地和六粒 20 分钟植物种子开始，完成播种、浇水、收获、育种、选择出售、购买与升级，关闭游戏后再回来仍能继续。首版做 20 分钟植物和 2 小时植物、六位每日客人、四种肥料、育种机、仓库与扩地。

好友互助、偷菜、赠种、小家园、小太阳、玩具和联网放在单人版验收之后。**主玩法发生在立体农场场景里**：固定斜俯视镜头，直接点击场景中的地块播种、照料和收获；商店、仓库等设施也放在农场中，打开后才显示相应面板。无需控制角色移动。地块与设施使用现有 GLB，PNG 仅作面板图标。

当前目录有玩法文档和 33 个独立资产的 PNG、GLB、Blender 源文件，尚无 `project.godot`。素材盘点智能体的结果到达后，在阶段 1 的资产映射表里标记“可直接用／需修正／缺失”，不让尚未定稿的客人姓名和第二种植物形象阻塞玩法开发。现有 `carrot` 只作为 2 小时植物的临时美术 ID，不代表正式命名。

## 实施原则

- **一轮地块是核心数据单位。**每块地保留独立的播种种子、播种时间、照料记录、遭遇、随机波动、成熟状态与收获批次 ID。五个可出售作物共享该批属性和经历；2～3 粒新种子逐粒生成。不同地块的作物批次不合并。
- **规则与画面分开。**界面只发出“播种、浇水、施肥、收获、购买、出售”等操作请求；单一规则层验证条件、改动存档并返回结果。以后加入多人时可以把这些请求交给服务端裁定，不必把算法从按钮脚本里拆出来。
- **用绝对时间恢复进度。**存播种和到期的 Unix 时间戳，进入游戏或打开界面时统一结算已到时的生长、遭遇和育种机产出；不靠持续运行的 `Timer` 来模拟离线时间。每日客人用北京时间日期作刷新键。单人版设备时钟可被修改，联机时再由服务端时间裁定。
- **随机结果可复现。**每轮播种保存随机种子或已抽出的结果；离线重进、反复打开界面和读档不得重抽属性、遭遇、新种子或报价。
- **先可玩，后铺满规则。**每阶段都有独立可试玩交付物。未定的少量价格与事件文案集中放配置表，并标明“试玩初值”，不写死在界面代码里。

## 阶段 1：建立工程与最小可玩闭环

1. 在 `E:\gpt\godot\farm` 建立 Godot 4.6.1 工程、立体农场主场景、输入与窗口设置；建立 `scenes/`、`scripts/domain/`、`scripts/world/`、`scripts/ui/`、`tests/`。建立资产 ID 到 GLB 模型和面板图标的映射，核对素材盘点结果；场景展示六块可点击土地、商店、仓库与少量状态信息。
2. 做 20 分钟植物的一轮：开局六粒无词条种子；点击空地选种并消耗一粒；真实时间到期后显示成熟；点击收获取得每地五个作物和独立的 2～3 粒新种子。先实现默认 `×1.2` 出售、商店买入基础种子，让玩家能连续种第二轮。
3. 接入最小本地存档：六块地、金币、种子、作物批次和时间戳。每次改变库存或地块后保存；读档后按当前时间恢复成熟状态。写入时采用临时文件加替换并保留可恢复副本，存档加版本号。
4. 给开发者一套仅在调试构建可用的时间推进和固定随机种子入口，避免每次验收都等待 20 分钟。

**验收：**玩家可从新档种满六块地，关闭程序，超过成熟时间后重进，逐块收获、默认出售、再购买并播种；重复读档不会凭空增加金币、作物或种子。此阶段完成即为第一次可玩。

## 阶段 2：完整种植、照料与成长规则

1. 加入 2 小时植物及“种地等级 + 商店等级”的解锁条件；首批种子由玩家购买。播种时锁定种地等级与植物等级，收获时按原定分钟数发经验、处理逐级门槛。
2. 实现每种植物的有效浇水时段、水壶等级和浇水加分；实现四种肥料每份十次、每次作用于地块两小时、不能覆盖未到期肥料。播种时已生效或生长中途施肥，都为当轮记录完整效果；过期不抹去已记录的当轮效果。
3. 实现每轮共享的 0～10% 随机波动、每株作物的基础分与各项加分，以及 20 分钟一条、2 小时两条的自动正向遭遇。把播种、照料、遭遇、收获写入该轮可读经历。
4. 加入收获结算面板、逐块收获和一键收获全部成熟地块；按地块显示每批的属性、分数构成和新种子，确保“一键收获”调用同一套结算逻辑。

**验收：**两种植物都能在前台与离线状态成熟；浇水窗口、肥料到期边界、两条遭遇相加、播种时等级快照和一键收获结果与逐块收获一致。收获时升级不改动刚收的那一轮分数。

## 阶段 3：属性育种、仓库与育种机

1. 建立每粒种子的唯一 ID、植物类型及最多四条词条。实现三项属性保底优先分配，再按倾向权重分配剩余点；种子显示品质只取最高分单条词条。
2. 实现每粒后代独立的“继承 → 单档晋升 → 按当前词条数判新词条”流程；变异肥料和保种肥料分别改变对应概率。规则参数集中配置，提供固定随机种子的计算测试和大量模拟报告，用于检查概率与目标育种节奏。
3. 实现作物区与种子区各 60／120／240／480 格、种子同属性同词条最多 99 粒叠放、不同地块作物分批存放。仓库满时保留待领取结果，并给玩家明确的整理或出售入口；绝不静默丢失产出。
4. 实现育种机购买、模板锁定、按**种子 ID**保存各模板未完成进度、离线复制、机内容量与手动领取；仓库满时副本继续留在机内。模板原种始终保留在仓库，复制品与模板词条完全相同。

**验收：**能从普通种子连续挑选后代培育词条；同一地块的新种子可不同；切换模板再切回可恢复各自进度；离线跨多个复制周期只产出到机器容量上限，满仓领取不丢种子。

## 阶段 4：每日客人、出售与经济升级

1. 实现六位客人的固定植物偏好，每个北京时间日期抽三位，并为两种植物各抽当日公式及系数。商店 2 级锁客人、3 级锁该客人对一种植物当天出现的公式类型；更换在下一次北京时间零点生效。
2. 做库存批次的拆分出售、三位客人的报价对比和默认出售。按“基础分与加分求和 → 乘最终倍率 → 整笔合计除以 100 向下取整”结算；金克拉先给最终倍率直接加 0.2。出售与库存扣减作为一次存档事务处理。
3. 接入商店批量购买及整笔购买价四舍五入、所有种子 5 金币回收、肥料价格、扩地、仓库／商店／水壶／育种机升级。把试玩经济数据记录为“每轮收入、种子肥料成本、净收入、到下一项升级所需轮数”。

**验收：**跨北京时间零点及离线数日后只显示当天客人；锁定规则正确延续；一批五个作物可拆给不同客人；低报价时可选默认出售；买卖种子无法套利；升级后功能、折扣、容量和存档状态一致。

## 阶段 5：玩家体验与素材整合

1. 根据盘点结果把现有地块阶段、作物、设施、肥料、客人和装饰放进统一视觉布局；补齐点击热区、悬停与选中反馈、成熟提示、进度显示、仓库筛选和种子词条对比。暂缺素材先用明确占位图与资产 ID，不改玩法数据结构。
2. 编写可读的正向遭遇文案，令事件文字与实际加分档位相符；完善收获面板、售价构成说明、仓库满提示、育种机满提示及首轮操作引导。
3. 在真实显示比例下试玩六地、十地、满仓、批量出售等高信息密度场景；调整排版、字号和操作步骤。声音、动画和 3D 展示只在不拖慢核心循环验收时加入。

**验收：**新玩家不看文档也能完成首次播种、收获、出售和再播种，并能读懂一粒种子为什么值得保留、同批作物为什么在不同客人处价格不同。

## 阶段 6：验证、平衡与交付

1. 用固定随机种子检查关键边界：空仓／满仓、关机前后、肥料恰好到期、浇水时段交界、跨日刷新、升级当轮、多人次点击同一按钮、读档恢复与存档版本迁移。对分数、金币和育种概率做规则层测试；每次修改规则后重跑。
2. 用调试时间推进快速跑早期 1～3 天和中期数十轮，再用真实关闭重启验证离线逻辑。对照玩法文档检查 20 分钟与 2 小时植物的基础小时收益、升级成本、育种节奏；记录调参依据，而不是只凭单次随机体验改值。
3. 清理调试入口、编写操作说明，制作 Windows 可运行包，保留源工程与可编辑素材；在 Godot 4.6.1 编辑器里导入后再做一次完整试玩。

**验收：**新档到育种机与每日客人形成持续循环；连续存读档不丢物品、不重复结算；无阻断流程的报错；导出包与编辑器运行结果一致。此时才把单人首版标为完成，并为好友、偷菜和小家园另立实施阶段。

## 建议的工程边界

| 部分 | 责任 | 建议位置 |
| --- | --- | --- |
| 静态配置 | 植物、肥料、词条、客人、升级价格等可调初值 | `data/` 下的 Godot Resource 或数据文件 |
| 规则层 | 地块状态转换、随机、计分、库存、交易与解锁 | `scripts/domain/` |
| 存档与时钟 | 版本化存档、离线恢复、北京时间日期 | `scripts/services/` |
| 画面 | 立体农场和地块在世界场景中；仓库、商店、客人、结算使用弹出面板 | `scenes/`、`scripts/world/` 和 `scripts/ui/` |
| 素材 | GLB 场景模型、PNG 面板图标与盘点清单 | 原件 `art/lowpoly/`，运行时副本 `assets/` |

规则层优先暴露清晰的操作函数和结果对象；界面通过信号刷新。节点使用明确名字或唯一节点路径，不通过宽泛的 `get_children()` 遍历猜测对象身份。存档存游戏数据，不存场景节点本身。

## 执行与验证命令

使用用户提供的 Godot 控制台程序：

```powershell
$godot = 'E:\其他\chorme_download\Godot_v4.6.1-stable_win64.exe\Godot_v4.6.1-stable_win64_console.exe'
& $godot --headless --editor --path 'E:\gpt\godot\farm' --quit
& $godot --path 'E:\gpt\godot\farm'
```

第一条用于首次导入和检查脚本／资源错误，第二条打开游戏供试玩；工程建成后 `--path` 指向**包含 `project.godot` 的目录**，不是 `claude.md`。做涉及 worktree 的开发时，也先在该 worktree 对应目录运行一次编辑器导入，再启动游戏。

## 参考调研

- [Farm Together 2 官方 Steam 页面](https://store.steampowered.com/app/2418520/Farm_Together_2/)：现实时间在离线时继续推进、回归后可继续经营，是本项目离线闭环的体验参考；本项目不照搬其角色移动与多人形式。

- [Godot 4.6 场景教程](https://docs.godotengine.org/en/4.6/getting_started/first_2d_game/05.the_main_game_scene.html)、[资源说明](https://docs.godotengine.org/en/4.5/tutorials/scripting/resources.html)、[存档说明](https://docs.godotengine.org/en/4.0/tutorials/io/saving_games.html)、[命令行说明](https://docs.godotengine.org/en/4.6/tutorials/editor/command_line_tutorial.html)：支持场景复用、数据与节点分离、版本化存档及命令行导入验收。
