# 2.9 整体平衡与交付体验：详细设计 v0.1

日期：2026-10-01。状态：完整体验与验证设计。[设计索引](第二大阶段详细设计索引.md)。本文定义什么样的游戏体验算第二大阶段交付，不是代码测试执行清单或发布操作指令。

## 1. 完成的定义

新玩家和已有 v5 农场玩家，都能准备、单人／双人进入两层洞窟、根据搜刮改变牌组、选择撤离或承担失败、带回资源用于农场与战备，并稳定保存恢复。

“完成”不只意味着一局偶然能打通。必须验证提前撤离、失败、满仓、掉线、原主机恢复和重复结果这几条现实路径。没有实际跨网络好友连接方式时，合作交付仍缺项。

## 2. 功能 D2.9-01：完整体验场景

| 编号 | 玩家情况 | 体验路线 | 必须看见的结果 |
| --- | --- | --- | --- |
| V2.9-01 | 全新玩家 | 农场教学 → 战备 → 单人短途撤离 | 找得到入口，看得懂牌与带回用途 |
| V2.9-02 | 已有 v5 老档 | 继续种地 → 第一次下洞 → 返回 | 原资产、词条、市场与育种机保留 |
| V2.9-03 | 普通装备单人 | 第一层 → 第二层 → 首领前撤离 | 深层资源可推进成长，不强求首领 |
| V2.9-04 | 追求挑战单人 | 两层 → 首领胜利 → 制作 | 有胜利高点和后续使用理由 |
| V2.9-05 | 两名好友 | 准备 → 支援 → 分享 → 共同撤离 | 两人各得自己的物品且能回自己农场 |
| V2.9-06 | 失败玩家 | 满载死亡 → 保护种子 → 基础装再出发 | 损失可解释、没有破产等待 |
| V2.9-07 | 仓库已满 | 撤离 → 待领取 → 整理 | 结束局不丢奖励、不重复领取 |
| V2.9-08 | 断线玩家 | 战斗／分享断线 → 重连 | 原状态与唯一物品归属恢复 |
| V2.9-09 | 主机退出 | 暂停 → 原主机恢复 → 结算 | 不因断线凭空成功或失败 |
| V2.9-10 | 写盘失败 | 已确定结算 → 重试 | 最多应用一次，失败提示真实 |

每条路线分别检查普通构建与最终 Windows 发布构建；本文只规定场景和结果，测试脚本及操作步骤由后续执行计划补齐。

## 3. 功能 D2.9-02：战斗平衡口径

先比较三类配装：基础轻装（免费 8 张＋少量补给）、普通战备（铜剑／加固盾＋恢复）、深层战备（铁装＋工具＋救援或能量补给）。每类均覆盖空包、半包货和满包货。

记录实际牌数、首回合牌数、有效攻击／防御比例、负担牌比例、每战回合数、生命损耗、补给使用和输赢。不能只记录“战力值”或胜率。

| 项目 | 初步观察目标 | 不达标时优先检查 |
| --- | --- | --- |
| 浅层普通战 | 多数 3～6 回合 | 是否敌人太脆或过度格挡 |
| 第二层普通战 | 多数 4～7 回合 | 铁装是否必要到排斥轻装 |
| 首领 | 熟悉规则者约 5～8 回合 | 是否只有固定牌序能过 |
| 三容器作用 | 背包与保险箱牌至少在部分战斗实际加入 | 战斗是否普遍两回合结束 |
| 装货代价 | 半包可感知，满包更明显但不是必输 | 负担牌费用、敌人压力与抽牌 |
| 合作支援 | 至少有可解释的救险或减少损耗场景 | 队友格挡／治疗是否不值得花能量 |

这些是诊断目标，不硬凑每场同样长度。抽牌好运可能更快，未知敌人可能更慢。允许不同流派，禁止免费抽牌／能量形成无需资源的无限循环。

## 4. 功能 D2.9-03：经济与成长平衡

每局区分带入装备价值、实耗补给、丢弃物、失败损失、新增可售收益、留下制作的材料和永久解锁。返还带入装备不是盈利，保护材料也不是凭空金币。

同时核算金币成本与材料机会成本，例如铜剑配方材料可售 36、另花 8，合计 44，而成品出售 40，不形成单纯制作套利。批量购买的四舍五入和商店等级折扣以现有口径计算。

至少比较基础轻装、普通战备、重装三种策略的 5 次、10 次和更长重复循环，不只取一局高价值掉落。记录成功、早退和死亡分别的收益分布。

初步目标：早期 1～3 次普通撤离能推进一个基础配方；第一次稀有植物收获能做出实际有用的补给；第一份铁矿明确指向深层装备；设施升级需要多局目标，但不要求连续全天守着农场。

农场高收入旧档与新档分别观察。已有玩家金币富裕可以快买补给，但独特资源与配方仍需探险取得；不能强行清空旧金币来平衡。若需要调旧农场价格或收益，先记录理由和旧档影响，再改规则。

保险箱记录“每局保护价值／携带总价值”及资源种类。初箱能保护重要种子合理，但不能稳定保住每局全部高价值货物；扩容后仍需要弃物和承担风险。

## 5. 功能 D2.9-04：撤离与合作体验评估

在两个撤离点记录玩家选择、生命、补给、已有收益和下一目标，并询问选择原因。目标是至少出现“已经拿到目标”“货物拖累牌组”“补给不够”“队友状态差”“还想找铁矿”等不同理由。

如果几乎所有人固定同一撤离点，判断是学习期还是永久策略优势。不要仅为了提高深层进入率降低一切风险；先看深层资源是否真的有用途。

双人记录回合等待、搜刮等待、路线分歧、公共物资归属、分享次数和救援意义。等待可以来自真实讨论，不能主要来自长动画、重复确认和排队点同一个按钮。

公共物资争取保留，但不做奖励统计羞辱少拿的一方。合作结算分别列个人收获，同时记录队伍成功；不排名“谁贡献最低”。

## 6. 功能 D2.9-05：新手与可读性评估

建议至少 4 名没有读过文档的试玩者，先各玩短途，再组成两对合作。观察第一次找入口、配装、出牌、拾取、撤离、制作是否需要开发者口头指挥。

首次受阻时记录玩家看到什么和尝试了什么，不直接把正确答案告诉他再宣称教学通过。设计通过条件是主要操作能自行发现，保护区和死亡损失能复述。

在 1280×800、1440×900 和 1920×1080 检查：费用和敌人意图可读、手牌不遮目标、背包可旋转、长名称不盖按钮、双人状态可识别、保存错误未被遮罩压暗。

关闭音效、快速动画、减少闪烁后仍能获取全部关键结果。网络慢时可区分“等待”与“点击没生效”，不会鼓励连点制造混乱。

## 7. 功能 D2.9-06：资产与恢复验收

对出发、分享、公共领取、撤离、失败、满仓、退出与重连核对账目：从哪里来、现在在哪里、为什么变化。每件具体装备最多归一个位置；同一结算最多应用一次。

保存／恢复不能改变固定奖励、敌人意图和牌库；暂停时经营农场不被恢复局覆盖。发布版不允许用调试发物、立即成熟或推进回合绕过正常玩法。

备份恢复有明确提示；无法恢复保留原数据与未决状态。原主机长期不在线的限制写在玩家指南，不能用“支持重连”遮盖它。

## 8. 功能 D2.9-07：玩家指南和发布体验

Windows 包有清楚名称与版本标识，首次打开进入正常农场，已有档自动按兼容设计升级，不把开发菜单作为首页。

玩家指南只需讲清安装／启动、农场入口、配装与容器、卡牌回合、搜刮、撤离与死亡、制作、好友连接、暂停恢复和存档位置。技术细节移到诊断附页，不让普通玩家读协议。

好友连接指南写实际可用的连接方式和需要输入的信息，并给连接失败的简短分类：版本不一致、主机不可达、房间已开始、身份不匹配。不能复制未实现的平台邀请说明。

版本更新说明列新增玩法、迁移范围和实际已知限制。内容图鉴只展示本版本可得到的装备、植物和敌人，不用未开发内容制造不存在的目标。

## 9. 功能 D2.9-08：缺陷与未定设计分类

| 类别 | 例子 | 是否阻止本阶段完成 |
| --- | --- | --- |
| 资产错误 | 丢装备、重复收益、旧档被重置 | 是 |
| 主循环中断 | 无法撤离、死亡后不能再出发 | 是 |
| 合作缺口 | 实际好友无法连接、无法分别结算 | 是 |
| 恢复错误 | 已确认状态不可恢复且没有明确边界 | 是 |
| 信息误导 | 实际未保护却显示保护、费用错误 | 是 |
| 核心体验失败 | 所有货物不影响战斗、没有任何撤离取舍 | 是，先改设计 |
| 内容不足 | 事件略少但必要类别齐全 | 可记录并调整预算 |
| 轻微表现 | 非关键装饰、少量声音不足 | 可记录，但不能影响辨认操作 |

不能因为开发量大就把合作或农场用途从“必须”降成“以后”。可以减少非必要内容数量，并如实更新总计划。

## 10. 设计验证报告应回答的问题

报告需写：哪些场景真正玩过；新旧档、单人双人的实际结果；数值初值如何变成当前版本；撤离选择为何成立；联机连接和恢复有哪些限制；仍未通过的体验是什么。

用截图、实际记录和固定输入算例支持结论；没有做过的写“未验证”。本阶段的设计完成并不等于游戏已实现，文档状态要等后续代码和试玩交付后再更新。

## 11. 后续扩展的解锁条件

只有两层闭环和恢复稳定后，才扩第三／四层、三至四人、更多配装、好友农场访问和自由家园。扩展优先复用已有物品、牌和节点规则；新增机制必须有清楚用途和独立体验验证。

第二大阶段完成的判断是：玩家愿意再出发，因为想拿到某种资源或尝试另一套配装；朋友愿意一起玩，因为保护、分享和共同撤离确实改变体验。
