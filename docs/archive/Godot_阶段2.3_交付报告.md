## 2. 验收对照（总计划 §10-2.3）

| 验收项 | 结果 | 证据 |
| --- | --- | --- |
| 物品占格与牌实例数量可核对 | 通过 | defs_smoke：15 种全部 `cards == w×h`；validate_definitions |
| 三个容器加入时点正确且不重复 | 通过 | combat_worked：首回合手牌全部胸挂来源；第 2 回合背包牌进抽牌堆 |
| 拾取在下一战生效 | 通过 | combat_worked：第二场按新布局重建（耗尽药水不生成） |
| 满包不吞物 | 通过 | inventory_worked：放不下回退、claim_reward 无半领取 |
| 药水多张来源牌不能多次消耗同一份实体 | 通过 | combat_worked：注入第二张饮药，耗尽后手牌/抽牌/弃牌全清 |
| 存读档保持布局和归属 | 通过 | save_smoke：旋转/格子/容器归属/剩余次数保留，牌组重建一致 |

设计 §9 的三种选择（种子入保险箱／铜剑换位／丢弃摆件少 4 张负担）在规则层全部可复现（inventory_worked 的丢弃断言＋combat_worked 的布局重建）。

## 3. 实施记录与偏差

1. **拖放为容器级**：拖到容器盒即自动找位（不挤旧物）；逐格放置预览（绿/红覆盖）留待 2.8 表现层打磨。设计 D2.3-02 的其余要点（虚影、Esc 回原位由"失败不移动"语义覆盖）已在。
2. **自动整理失败恢复**：代码路径为整体恢复原布局；4×4 小容器内找不到"贪心放置必失败"的可测用例，该分支以代码审查覆盖并在本报告记录（总计划 §12.1"自动整理"行部分由成功路径＋归属保持断言覆盖）。
3. **岩芽菜种子售价值**：暂记 2 且 `sellable=false`（"回家按种子回收规则"2.5 接入，计划待澄清 #3 维持）。
4. **演示连战的生命延续重置点**：关闭战备面板时重置 carried_hp（一次整理会话内连战延续，符合"各场战斗生命延续"）。
5. 视觉转录再次出现串图（把 2.1 截图文字读进 2.3 截图）；以数值断言＋像素采样确认（背包区检出摆件紫/铁矿灰绿色块，与 2.1 图差异 6 万像素）。
