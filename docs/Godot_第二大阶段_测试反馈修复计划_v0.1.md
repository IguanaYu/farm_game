## 3. 批次 A：资产正确性（F-01、F-02）

### F-01 实例 ID 统一分配

- **根因（已核对）**：`expedition_game.gd:344` `run_inventory()` 与 `:218` `member_inventory()` 每次 `bind()` 一个新建字典，`next_instance_id` 按值拷贝；`InventoryGame.next_instance_id()`（`inventory_game.gd:52`）递增的是包装字典，`run["next_instance_id"]` 永不前进。同局多次取库存视图 → 全用同一编号（实测 3 件战利品全为 1003），`apply_settlement()` 按 ID 去重丢物。
- **改法**：实例编号的**唯一权威**是局状态字典（`run` / 成员 `info`）。让所有局内库存视图直接 `bind()` 含 `inventory` 与 `next_instance_id` 两个键的那份字典本身（`run` 已同时含两键，直接绑定即可；勿再复制包装），或分配后立即写回。单人、双人、分享、拾取、结算走同一边界；`apply_settlement()` 的 `maxi()` 合并逻辑保留作为防御。
- **新增回归**（建议进 `d24_run_smoke` + `d26_combat_coop_smoke`，覆盖单/双人两条路径）：
  1. 连续领取 3 件不同物品 → instance_id 严格递增且唯一；
  2. 中途 `restore()` 后继续领取 → 与恢复前不冲突；
  3. 撤离结算逐件对比撤离前后库存（数量/类型/使用次数）；
  4. 同一 settlement 重复 apply → 库存不变（幂等）。

### F-02 节点奖励一次性消费

- **根因（已核对）**：`expedition_map_panel.gd:382` `_on_claim_reward()` 只做"放置"，不做"消费"：二选一领取成功后把 `resolved["rewards"]` 重设为 `[def_id]`（等于还能再领）；采集类路径完全不消费候选。
- **改法**：消费语义放**规则层**（新入 `ExpeditionGame`，如 `claim_node_reward()`）：校验候选在 → 尝试放置 → 成功才把该条目从候选移除或标记 `claimed`；满包失败时候选保持。UI 层只调规则层并按返回刷新。**不允许**只在 UI 隐藏按钮（读档/恢复路径会绕过）。
- **新增回归**：
  1. 普通战斗二选一：领 A 后候选清空，再领被拒；
  2. 采集：每条奖励各领一次，第二次被拒；
  3. 领取→存档→读档→再点：仍被拒；
  4. 满包时候选保留，腾空间后可领。
- **复测口径**（两缺陷共用，反馈原文）：多节点连续领取 → 退出恢复 → 撤离 → 逐件入库对账；随后**重跑 `d29_economy_sim`** 出新结论。

## 4. 批次 B：合作闭环（F-03、F-04、F-11）——关键路径

### B1（commit ③）：出发确认与准备切换（F-03、F-11）

- **根因（已核对）**：`room_panel.gd` 无 `confirm_depart()` 调用、未连 `client.run_received`（收到 `depart_begin` 只存 `pending_run_id`）；`_on_ready()` 客机分支固定 `set_ready(true)` 不能取消。
- **改法**：
  1. 客机收到出发请求：先完成本地保存，成功后 `confirm_depart()`；**保存失败必须回执拒绝并提示原因，阻止开局**；
  2. 客机连接 `run_received`：正式局快照到达 → 切换到客机局界面（复用 `CoopClientPanel` 或直开地图镜像）；
  3. `_on_ready()` 客机分支改为按主机确认的成员状态切换 `set_ready(not current)`，成员列表即时刷新；主机侧在有人未准备时禁止出发。
- **回归**：现有 `d26_session_smoke` 直接调确认接口，**不能关闭本项**。新增同进程双 `RoomPanel` 场景探针（参照 QA `qa_runtime_probe` 手法固化为正式测试）：双方点真实按钮 → 不手动调任何接口 → 断言开局信号、客机界面切换、取消准备后主机不能出发、保存失败注入阻止开局。

### B2（commit ④）：共同裁定与客机战斗操作（F-04）

- **根因（已核对）**：`expedition_map_panel.gd:347` `_on_move()` 直接调单人 `expedition.move_to()`，未经 `SessionHost.host_action("vote_move")`；`CoopClientPanel` 只有固定列 0 的前进/领取/撤离按钮，无手牌/目标/结束回合/救援/分享；`battle_screen.gd:232` 固定操作 `p1`。
- **改法（三步）**：
  1. **地图裁定**：地图面板检测合作局时，移动/领取/撤离/放弃全部改走会话入口（主机 `host_action`、客机对应请求），一人投票不前进、双票才前进，镜像一致；
  2. **战斗操作通用化**：`BattleScreen` 增加 `player_id` 参数（不再固定 `p1`），出牌/目标/结束回合改为向"会话裁定入口"提交指令；客机 `CoopClientPanel` 直接复用 `BattleScreen` 展示自己的视角，删掉"出牌由主机界面或测试入口裁定"占位；
  3. **补齐客机动作**：分享、救援、分配操作的按钮接入同一入口。
- **回归**：扩展 `d26_combat_coop_smoke`：双端独立出牌与结束回合、共同撤离、分配一致；再加"一人投票不前进"断言。
- **验收门槛**（反馈原文）：两个独立进程用真实房间按钮完成建房、加入、准备、取消、出发、双端各自出牌打完一场、分配、共同撤离——禁止测试脚本代替 UI 调用。此项通过前，合作交付状态保持"未完成"。

## 5. 批次 C：场景接入补齐（F-05、F-08）

### F-05 萤果场景模型

- **根因（已核对）**：`farm_world.gd:20` `STAGE_MODELS` 缺 `glow_berry`（`_refresh_plot_model()` 直接下标访问 → 每次刷新报错、地块永远空地模型）。HUD 图标缺键已在巡检轮修掉，但场景模型未动。
- **改法**：按 `rock_sprout` 先例补 `glow_berry` 三阶段（暂用胡萝卜模型占位，正式素材后换）；同时给 `_refresh_plot_model()` 加兜底：未知 kind/stage 回退空地模型并 `push_warning`，不再抛错。
- **回归**：新增 headless 场景测试（3D 实例化不需要窗口）：四种植物 × 全部生长阶段 × 载入存档刷新 × 成熟标记，断言无脚本异常且模型键正确。

### F-08 播种引导时序

- **根因（已核对）**：`farm_world.gd:526` `_on_plant_seed_requested` 顺序是 播种 → `_save()` → `_refresh_all()` → `_advance_tutorial(0)`；`_advance_tutorial()` 只改内存不保存不刷新 → 播种后磁盘还是旧步骤、横幅不动，必须再做一次别的操作才可见。
- **改法**：动作成功后**先**推进引导，再统一保存 + 刷新（浇水等同批次检查所有引导触发点的顺序）；"跳过引导"立即保存。
- **回归**：场景探针断言：新档播种后 `tutorial_step` 内存与磁盘一致、横幅刷新；退出重开保持；跳过后重开不再出现。

## 9. 工程注意事项（本阶段高频坑，新代码必读)

- **PanelContainer 不是竖向堆叠**：多行内容必须内嵌 VBox，否则子节点互相覆盖（结算弹窗已中招）。
- **Label autowrap 在 HBox 里会塌成一字竖柱**：`_label()` 默认不换行，长文本处显式开 `WORD_SMART`；标题 `AUTOWRAP_OFF`。
- **常驻全屏覆盖层**：隐藏时 `mouse_filter` 必须 IGNORE，弹出再 STOP，否则吞掉底下全部点击。
- GDScript：禁命名参数调用；`match` 分支禁 `break`；字典链式下标赋值要局部变量中转；新 `class_name` 要先 `--headless --editor --path . --quit` 注册再跑测试。
- 跨存档比较字典不要 `str()` 逐字比（JSON 往返数值变 float），按字段语义比（d24 已改出先例）。
- 改 `SAVE_VERSION` 需同步 6 个旧 stage 测试断言（本计划不动存档结构，预计不触发）。
- 截图类测试必须去 `--headless`；巡检前备份 `user://`，跑完恢复。
