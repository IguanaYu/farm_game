## 3. 数据与存档

- 个人档版本：**不再升版**。以 2.5 交付的 `SAVE_VERSION=7` 为准（若 2.6/2.7 交付已再升版则跟随其版本号），本阶段新字段全部按 2.7 先例 `get(field, default)` 容错读取、缺省即"未解锁/未完成"，不触发迁移分支。
- 个人档 `expedition` 块新增（声明后落码，A1-5）：

```text
expedition: {
  tutorial: {                       # D2.8-07 教学进度（老档缺省视为未开始）
    step: String,                   # 当前步骤 id；""=未开始
    finished: bool,
    reward_settlement_id: String    # 教学奖励锚点，见下
  },
  depth: {
    max_floor_reached: int,         # 0=未入洞；2.4 已有"最高到达层数"显示则迁移复用其字段名
    floor2_unlocked: bool           # 守门战胜利一次即置位（老档缺省 false，不影响第一层）
  }
}
```

- 教学奖励走同一结算逻辑（复用点，总计划 §8.3）：教学局结束生成固定结算 ID `settle-tutorial-<player_id>`，经 2.4 的 `FarmGame.apply_expedition_settlement`（单事务幂等）应用并登记进 `applied_settlements`；奖励内容为一次性真实少量铜片与纤维（数额见 §6 待澄清 b）。跳过教学不发；重放教学时同 ID 被 `applied_settlements` 去重、只回执不再发物——不新做第二套发奖路径。首领一次性成长里程碑同理走 2.5 `crafting_defs` 目标系统（一次性发奖幂等），重复击杀的普通收益走第二层奖励池。
- 局档（`user://expeditions/run_<run_id>.json`）：`fmt` 1→2。新增 `floors` 结构（两层地图数据与每层进度）与 `floor_exit` 层间出口状态；两层地图在同一出发事务内一次生成并写入初始快照（设计 §2"本局出发时已固定"），层间不重生成、恢复局不重生成（2.7 重放兼容）。读到 `fmt:1` 的旧局档时 `floors` 缺省按"仅第一层"容错，其余字段不变；`fmt` 大于 2 仍按 2.7 规则拒绝。
- 设置档（新档，先声明）：`user://settings.json`，三段式写入（复用 `SaveStore` 写法、路径注入），与主档分离——仅改设置不触发农场保存。字段：`music_volume`、`sfx_volume`（0.0~1.0 线性，映射 `linear_to_db`，0 值置总线静音）、`animation_mode`（`"normal"|"fast"`）、`reduce_flicker`（bool）、`ui_scale`（1.0/1.25/1.5，映射窗口 `content_scale_factor`）。首档生成默认值；测试用注入路径 `user://d28_*.json`。
- `PROTO_RULES_VERSION` 本阶段默认不动（版本号由 2.9 冻结时统一推进，见 §6 待澄清 g）。

### W2 第二层地图与层间衔接（D2.8-01）

- 文件：`expedition_defs.gd`（生成参数）、`expedition_game.gd`。
- 要点（第二层生成参数与层间衔接）：
  - 生成参数集中在 `expedition_defs.gd`：层名、8 排结构、各排节点倾向（设计 §2 表逐排落表）、每排候选数 1~3、4/7 排撤离位；第二层节点类型全部可见、奖励与敌人进节点揭示（复用 2.4 揭示规则）。
  - 两层地图在出发事务内一次生成（同一随机数推进状态写入初始快照），层间不重生成；生成后跑 `validate_floor2` 自检：每条合法深层路线至少一个铁矿机会（战斗或采集均可）、撤离排连通、无必经死路（复用 2.4 连通校验扩展到第二层）。
  - 层间出口：第 8 排守门战胜利后显示三选一——立即回家（走 2.4 撤离结算）、进入第二层、整理（打开随身整理，不离开出口）；进入第二层前显示说明文案（铁矿、萤果种子、更高品质装备可出现，仍会损失的当前货物）。生命与补给延续，格挡/手牌/抽弃牌等临时战斗状态清除（复用 2.4 战后清理），不免费恢复满血。
- 接口草案：

```gdscript
# expedition_game.gd 追加（域层、纯函数、时间注入）
```

### W6 表现事件播放器与音频（D2.8-08 声音与表现基座）

- 文件：`present_event_player.gd`、`audio_director.gd`、`default_bus_layout.tres`、`farm_world.gd`（实例化）、设置档读写。
- 要点（表现层消费事件列表的约定——总计划 §5.1/§8.2 红线的落地）：
  1. 规则层结果字典的 `events` 列表（A1-1 约定）是表现层唯一输入；播放器**只读**消费，播放完成、跳过或清空队列都不回调规则层、不产生第二次伤害或第二次扣费——伤害与状态变化在规则裁定内一次结算完毕。
  2. 同一份 `events` 重复播放后规则状态零变化（可断言）；长动画不阻塞合法操作：动画等待不是出牌/拾取裁定的前置条件，快速模式与点击跳过后立即可继续操作。
  3. 表现层不推进玩法随机（总计划 §9.2）；跳过动画后仍有文字结果（战斗日志与结算行承载价值信息，设计 §9"不能把价值只写在动画里"）。
  4. `animation_mode` 与 `reduce_flicker` 由设置档驱动播放器；减少闪烁只改表现参数（时长/频率/透明度脉冲），不改事件内容。
  - AudioServer 音效结构与音量设置：总线布局 Master→Music、SFX（`default_bus_layout.tres`）；`audio_director` 维护池化 `AudioStreamPlayer`（SFX）与一路 `AudioStreamPlayer`（Music，低干扰环境声与音乐）；音效八类按设计 §9 清单建 id：`ui_click`/`ui_error`/`play_card`/`hurt`/`block`/`pickup_rare`/`evacuate`/`fail`；音量设置映射 `AudioServer.set_bus_volume_db(bus_idx, linear_to_db(v))`、0 值 `set_bus_mute`；音效关闭后反馈完整性由文字与表现动画承担（W7 验收）。
  - 设置档 `user://settings.json` 读写见 §3；`farm_world.gd` 启动时实例化 `audio_director` 并应用设置，不新增 autoload。
- 接口草案：

2. 两层收益风险差异：同一试玩者分别完成第一层短途与进第二层局，能指出资源（铁矿/萤果/高品质装备）、敌人与风险的差别；首领前存在合理的提前回家选择。
3. 教学奖励只发一次：完成教学→记录存档→重放教学→存档核对 `applied_settlements` 无新增、物品无重复。
4. 双人满包、长名称、小窗口（1280×800）：拾取、分享、共同撤离全流程可操作，队友面板不遮手牌。
5. 模型与动画不影响规则时序：正常/快速动画与跳过后，战斗日志与结算数值一致（对照 `d28_presentation_smoke` 结论）。
6. 音效关闭后仍有完整文字与表现反馈；音乐/音效音量与界面缩放设置重启后保持。
7. 内容四步检查（设计 §10）：对每类新内容各抽一件走"能获取、能看懂、能使用、能回家处理"。

## 6. 风险与回退

- 红线（不可越，总计划 §8.2/§5.1）：**表现层不得影响规则时序**——动画队列只读消费 `events`、不造成第二次伤害或扣费，长动画不阻塞合法操作，表现不推进玩法随机；`d28_presentation_smoke` 是本红线的守门测试，任何表现打磨提交翻红即回退该提交。
- 技术风险：
  - `combat_game.gd` 经 2.2~2.7 扩展后体量大：精英/首领行为以独立行为函数＋定义表数据落在既有敌人协议上，不重写回合引擎；回退 W3 不影响 W1/W2。
  - 新素材 `.import` 缺失导致 headless 引用失败：W8 流程要求先导入后引用，CI/验收脚本在跑 `capture_d28_ui` 前执行一次 `--headless --import`。
  - 首领阶段与 2.6 目标指派/2.7 恢复交互复杂：`d28_boss_smoke` 含双人快照往返与暂停恢复后意图不变用例；裂解"下一次新意图生效"若与恢复语义冲突，以意图不变性优先。
  - 教学局分叉导致规则复制：教学局是受限 run 配置（固定路线＋demo 装备），所有裁定仍走 2.4/2.2 同一规则入口；发现第二套分支即视为缺陷。
  - 音频资源与授权：八类音效若临时采用 CC0/自制混音，逐条登记来源；无授权信息的素材不接入。
  - `farm_hud.gd` 已庞大：本阶段对它零改动（§2 边界说明），新 UI 一律独立文件。
- 回退策略：W1 纯定义表、W2/W3 规则扩展、W6/W7 表现层各自独立提交；任一回退不影响其余（表现层接入点是开关式的：`present_event_player` 可整体禁用回到文字/瞬时反馈）。设置档与 `fmt:2` 为增量字段，回退后旧代码按缺省读取。
- 待设计澄清（开工前或对应工作包前确认，结论回写设计文档）：
  - a) 白菜汤/岩芽药剂/救援包与 2.5 已入库补给成品的合并口径：def_id 复用、数值与来源牌以 2.8 设计 §5 表为准还是以 2.5 交付为准（涉及 §5 预算表计数方式）。
  - b) 教学奖励的具体数额（设计 §8 仅"一次性真实少量铜片和纤维"）与是否计入 2.5 目标进度。
  - c) 首领双人"对明示目标攻击"的目标选择规则（碎石投掷/重击选谁：固定交替、最低生命还是仇恨；设计 §4 未定）。
  - d) 层间出口"整理"选项的边界：仅随身容器整理，还是允许查看仓库/保护区（设计 §2 未细化；倾向仅随身，避免层间出现免费全量整理）。
  - e) 首领"一次性成长里程碑/一次性外观"的奖励形式与内容（设计 §4 末段未定外观所指）。
  - f) 动画"快速"档倍率与"减少闪烁"的适用效果范围（工程初值：快速＝0.4 倍时长；闪烁＝高频透明度脉冲与屏闪，待设计确认）。
  - g) `PROTO_RULES_VERSION` 是否随第二层规则扩展推进：本计划默认不动（避免开发期联机版本检查频繁失效）、2.9 冻结时统一推进，需设计/总计划确认。
  - h) `ui_scale` 三档是否本阶段交付（设计 §9 仅"窗口缩放"）：若实现成本超预期，可降级为"仅支持 1280×800 起的最小窗口"并移入 2.9，需确认。
