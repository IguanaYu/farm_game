## 1. 目标与非目标

**出口**（路线图 R4）：

> 配装/组队/出发/奖励/撤离一路连贯；已有活动局、队友未准备、断线重连都有正确入口和说明。

**非目标：**
- 洞内探索画面的场景化重制（地图/战斗 UI 沿用 OnlineRunPanel/地图面板——稿 §6"沿用卡牌战斗"；洞内地貌表现随 R5 打磨）。
- 选层功能（稿 §6"三层共用营地，通过洞口工作区选层"——当前规则出发即浅层，选层入口先不做，UI 预留）。
- 不改探险规则与 M3 协议。

## 2. 营地场景（稿 §6 位置表第一行）

新地点 `CaveCamp`（Node3D，注册 router "cave_camp"，同 ShopInterior 模式：碰撞层随切入/切离开关 + 营地相机低近俯角）：

| 实体 | 构成 | 点击行为 |
| --- | --- | --- |
| 山体洞口 | 灰岩壁斜面 + 内嵌暗色洞腔（深度用内壁渐暗 box 近似）+ 洞口冷光沿 | 打开发射界面＝现有 expedition_hub 面板（单人出发/继续/查看层介绍；线上=同面板走 M3 分支） |
| 篝火 | 石圈 + 柴堆 + 暖光火焰（发光锥） | 组队＝farm_hud.open_room()（离线房间面板 / 线上 OnlineRoomPanel 自动分流） |
| 战备台 | 木台 + 发光沿 | 配装＝hud.open_loadout()（M2 配装命令在线离线均可用） |
| 帐篷 | 三棱柱（PrismMesh）装饰 + 门口提灯 | 无点击（装饰） |
| 下山路口 | 路径石板 + 路灯 | router.go_back()（回农场） |

农场侧：东南紫盒 CaveEntrance 占位删除；上山石阶（R3 已建）点击改由 cave 入口分发改为 `router.switch_to("cave_camp")`（石阶＝"去洞窟营地"，营地内点洞口＝"进入洞窟"——稿 §6"避免把上山误当成立即开战"）。

## 3. 探索衔接（流程连贯）

1. **出发**：营地洞口 → hub 面板（现有 `_on_depart_requested/_on_resume_requested` 离线/线上分支不动）→ 成功后 OnlineRunPanel/地图面板照常打开（面板在 CanvasLayer，地点无关）。
2. **撤离/结算**：结算面板关闭后回到农场（现状）改为**回营地**（稿 §6"入口营地接住一次完整结算"）：局终（outcome 非空）时若当前地点为营地则留在营地；结算面板关闭回调里 router 切回 cave_camp。
3. **断线重连**：M3 welcome 恢复已直回局面板（S05）；面板关闭后玩家仍在农场/营地——不强制切地点。
4. **队友未准备**：OnlineRoomPanel 的错误文案已覆盖（M3）；篝火入口在营地即可见。

## 4. 测试（d49）

`tests/d49_cave_camp_scene_smoke.gd`：
1. 结构：CaveCamp 存在且默认隐藏；山壁/洞腔/篝火/战备台/帐篷/下山路口节点齐全（meta/名字断言）。
2. 路由：石阶入口 → switch 后 current=cave_camp、营地相机 current；下山路口回调 go_back 后回 farm、农场相机还原。
3. 流程入口：洞口/篝火/战备台的 input_event 绑定目标正确（分别 hub/open_room/open_loadout——以绑定存在+处理器调用模拟断言 hub 面板可见）。
4. 零重建：farm→营地往返 3 次 game 实例不变。
5. 全量回归：现有 55 项零变化（紫盒删除不影响任何测试——无引用）。
