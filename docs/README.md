## 目录结构

```
docs/
├── Godot_第二大阶段_农场与合作洞窟_整体开发计划_v0.1.md   ← 顶层总计划（当前活跃，子阶段 2.1～2.9）
├── design/        ← 设计文档：第二大阶段九份详细设计、核心玩法方向、玩法循环规则、聊天纪要、美术创意图鉴
├── plan/          ← 代码执行计划：第二大阶段九份 Godot 代码执行计划与索引（2.1 附录 A 为全阶段工程约定）
└── archive/       ← 第一大阶段（单人首版）全部已完成文档：交接版、任务书、交付报告、算例与模拟

screenshots/       ← 界面截图（项目根目录，不在 docs 内）
```

- `docs/.gdignore`、`screenshots/.gdignore` 使 Godot 不导入这两个目录。
- 顶层只放最高级别的总开发计划。第一大阶段（单人农场首版，原阶段 1～6）已全部完成、整体归档；第二大阶段（农场与合作洞窟）尚未开发，以顶层计划为准，后续每完成一个子阶段，其任务书与交付报告进 `archive/` 并更新顶层计划状态。

## 阅读顺序建议（新会话接手开发）

1. 根 `README.md`（玩法速览与启动命令）
2. `docs/` 顶层第二大阶段整体开发计划（当前要做什么、怎么验收）
3. `design/第二大阶段详细设计索引.md`、2.1 共用基线、当前子阶段详细设计（具体功能、交互、规则与设计验证）
4. `plan/第二大阶段代码执行计划索引.md`、`plan/` 中 2.1 附录 A 与当前子阶段代码执行计划（文件、存档、工作包与验收）
5. `design/` 核心玩法方向与玩法循环草案（设计依据与农场规则细则）
6. 需要时再看 `archive/` 中第一大阶段的交接版、任务书与交付报告

## 维护约定

- 顶层只放总开发计划；新的大阶段计划放顶层并更新本索引。每个子阶段完成后的任务书与交付报告进 `archive/`（建议按 `Godot_阶段2.1_...`、`Godot_阶段2.1_交付报告.md` 命名，与第一大阶段文档区分）。
- 详细设计放 `design/`、代码执行计划放 `plan/`，均持续维护，不因为代码阶段完成而归档。代码执行计划引用 `D2.x-编号` 功能，遵守 `plan/` 中 2.1 附录 A 的工程约定；设计里的新数值未经试玩不能标为已确认。
- 截图统一放 `screenshots/`（由 `tests/capture_*.gd` 脚本生成），不要放回 `docs/`。
- 历史报告正文中的结论性记录不回改；仅在其引用的文件路径变化时同步更新路径，保证链接可用。
