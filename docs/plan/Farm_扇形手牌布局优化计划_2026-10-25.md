# 扇形手牌布局优化计划

2026-10-25。用户已确认五张与十张的视觉方向，并授权实施。状态：已接入共享战斗界面，真实输入专项、相关回归与 Windows 导出完成。验收见 `docs/testing/Farm_扇形手牌_实施与验收_2026-10-25.md`。

## 实施约定

- `HandFan` 统一计算 0～10 张牌的位置、角度、抬升与命中；森林与普通战斗共用，卡面及战斗裁定沿用现有入口。
- 输入命中使用原扇形槽位与抬起后的牌面，悬停切换取消前一个动画；不在鼠标进入时重新生成整手牌。数字键 1～9／0 对应第 1～10 张，右键／Esc 撤销选择。
- `BattleScreen` 按 UID 复用按钮，显示尺寸、来源或卡面发生变化时更新内容。抽牌与出牌后只重排剩余控件；合作异步裁定接受前保留原牌和槽位，阻止重复提交。
- 拖放使用完整卡面预览，原槽位暂时淡化；拖放取消恢复卡牌姿态。能量不足只禁用出牌，仍能抬起阅读。
- 手牌区域移除厚底板，保留战场高度；能量和选择说明置于左侧，牌堆在左下，结束回合在右下。小窗口与十张满手共同约束操作区边界。
- 正常动画约 0.16 秒；已有快动画／减少动态设置下立即到位。弹窗、设置和战斗结束遮罩继续阻断卡牌输入。
- 验收使用实际鼠标移动、按下／释放、拖放、数字键、取消与模态输入；覆盖两种窗口、各手牌数量、合作等待与来源卡面。保留静态样稿用于视觉对照，最终截图来自正式接入后的控件。

## 改造前

`BattleScreen` 用 `ScrollContainer + HBoxContainer` 排列手牌，间距 10。五张牌居中横排，超过宽度时横向滚动；悬停只略微提亮。卡面已有米纸外框、衬纸图窗与费用章，普通窗口 148×236，最小窗口 132×204。

当前主要问题是手牌像一排列表，深色大底板占据战场，十张手牌需要滚动查看。直接旋转现有 HBox 内的卡牌会产生裁切、点击和重排问题，需要独立布局容器。

## 建议效果与初始参数

保留现有插图与卡框，改成画面底部居中的浅扇形；去掉整块厚底板，将能量放左侧、结束回合放右侧，牌堆入口留在左下。中间牌最高，两侧轻微下沉和旋转，底部保留名称以外的特殊规则与快捷键。

| 状态 | 初始建议 |
| --- | --- |
| 1 张 | 居中、零旋转 |
| 2～5 张 | 少量重叠；五张最外侧约 ±10°，横向步距约 120 px |
| 6～10 张 | 逐渐压缩步距；十张时普通窗口步距约 74 px、最大角度 ±16°，小窗口步距约 49 px、最大角度 ±13° |
| 悬停／数字键选中 | 抬高 65～80 px、转正、放大约 1.18 倍、置于最上层；相邻牌轻微让位；角色预览较高时自动降低抬升 |
| 选择目标 | 所选牌保持抬起；目标高亮、伤害预览使用已有流程 |
| 抽牌／出牌 | 约 0.15～0.22 秒补位；出牌期间保留槽位到裁定接受，避免误点 |
| 1024×640 | 用 132×204 卡面，减小角度和抬升；优先保留角色生命与敌人意图 |

以上参数已接入运行，仍可根据真人试玩微调。满手时底部文字会有遮挡，完整规则由抬起的卡牌和悬停说明阅读；所有牌的费用与可选区域必须能辨认。

## 实施顺序

1. **独立布局容器**：增加 `HandFan`，负责位置、角度、缩放与层级。按手牌数量和可用宽度求步距，移除手牌滚动裁切；用真实旋转后的四角检查边界。卡牌样式和结算继续复用。
2. **稳定的悬停与选中**：按鼠标命中选择最上层可见卡；给抬起前后的区域留连续命中范围，避免卡牌移动触发反复进出。转移悬停时取消旧动画，维护唯一悬停牌；无法出牌的卡也可抬起阅读。
3. **接入已有操作**：保留点击选牌、拖向目标、自用牌立即出牌、数字键、右键／Esc 取消。拖出时用完整卡面跟随鼠标，取消后回到槽位；合作等待裁定时锁住提交中的卡牌。
4. **减少重建造成的跳动**：当前 `_refresh_hand()` 清空并重建所有按钮。改为按卡牌 UID 复用控件；新增、移除和能量变化分别更新，避免悬停丢失及补位闪动。
5. **收尾验证**：森林试玩和普通战斗共用组件；验证单人、合作视角、目标预览、牌堆弹窗、战斗结束遮罩。兼容现有快动画设置。

## 验收

- 1280×800 与 1024×640 下，0／1／2／5／8／10 张牌都能查看并选择；两侧牌不出屏，费用不全被遮住。
- 悬停中间和两侧牌均可完整阅读；沿牌顶快速划过、在重叠区域停留时不抖动、不选错牌。
- 悬停与选择不遮住角色生命、敌人意图、主要目标点击区和结束回合按钮。
- 点选、拖放、数字键、取消、能量不足、抽牌、出牌补位和合作等待均保持原有裁定；布局和预览不改变战斗状态或随机数。
- 执行相关现有卡牌 UI／森林卡牌回归，并补充有实际输入的扇形交互验收；静态截图不视为交互验收通过。

## 十张满手补充样稿

用户认可五张牌的视觉方向后，询问十张满手的处理。保留当前卡面大小，增加扇宽与重叠；每张牌露出左上费用和部分插画，牌名及规则允许被邻牌遮挡，悬停后抬起、转正再完整阅读。十张同时在窗口内，不用横向滚动；正式交互应允许沿牌顶逐张划过，并保留数字键选择。

## 实施结果

共享 `BattleScreen` 已使用 `scripts/ui/hand_fan.gd`，替代横向滚动容器。五张浅扇形与十张密集扇形、悬停抬牌、所选牌保持展开、完整卡面拖放、取消归位、按 UID 补位、禁用牌阅读及合作待裁定槽位均已接入。能量、牌堆与结束回合沿用确认的摆放方向，长说明使用紧凑换行浮窗。

命中同时考虑固定费用区域、原槽位与展开后的牌面，连续划过十张牌时不会因牌面放大而吞掉邻牌的切换区域。重排不重建现有按钮；来源、顺序或窗口大小改变时刷新卡面。窗口缩小时立即重算边界，已有减少动态设置下省去补间动画。角色状态与目标预览较高时，手牌自动留出 8 px 间隔。

`tests/hand_fan_smoke.gd` 的真实 GUI 输入专项通过 2473 项检查；覆盖 1280×800 / 1024×640、0／1／2／5／8／10 张、悬停稳定与逐张划过、键鼠选牌、拖放成功／无效区域／右键取消、能量不足、模态输入、p2 第十张与合作回执。普通试玩、森林两批卡牌、品质反馈、旧战斗入口、状态与费用锚点回归均通过。正式截图在 `screenshots/hand_fan_live_2026-10-25/`，Windows 试玩包为 `build/Farm.exe`。

补充截图验收：`screenshots/hand_fan_acceptance_2026-10-25/` 提供 18 张原图、总览与逐图状态摘要。截图发现的拖放插图缺失已修复，新增纹理／原生插画保留断言后专项通过 2475 项；Windows 包已同步更新。
