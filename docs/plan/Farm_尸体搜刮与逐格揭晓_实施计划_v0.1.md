日期：2026-10-05。状态：用户授权后已完成 P1～P3 的本地实现与验证，并重新导出 Windows 试玩包。所有时长、数量与格子尺寸仍为待试玩初值；公网服务部署和真人双机试玩尚未进行。

实施记录见 [尸体搜刮实施与验收](../testing/Farm_尸体搜刮实施与验收_2026-10-05.md)，预览见 [真实引擎画面](../../screenshots/corpse_loot/README.md)。下文保留原计划；最终落地以本节及实施记录为准。

实际落地说明：

- 用户同日补充多格表现：未知物品公开实际占格轮廓，搜索圆环覆盖完整物品区域；盾牌 2×2、短剑 1×3，揭晓与装包沿用同一尺寸。此补充替代下文最初提出的“隐藏占格轮廓”。轮廓不含物品定义、实例 ID 或属性。调整后 d54 无头 135 项、真实窗口 133 项检查通过，真实 ENet 和 WSS 复验通过，并再次导出试玩包。
- 固定内容在节点首次裁定时生成，战斗全场胜利后开放搜索；不会在战斗中搜刮。
- 战后使用共用洞窟与人物绘制组件，敌人按遭遇顺序显示倒地形象。战后来源选择是独立组件，不与正在战斗的牌区叠加。
- 新增 `scripts/domain/corpse_loot_game.gd` 集中管理固定布局、计时、区域占用及可见投影；新增 `scripts/ui/corpse_loot_stage.gd` 与 `corpse_search_grid.gd`，复用已有玩家格子与装包事务。
- 物品搜索 850 ms、空格 110 ms；首版没有额外开包延时和持续循环音，揭晓沿用开包提示音。速度不随隐藏品质变化。
- 骷髅使用实际固定配装：铜短剑与皮护腕，腰包带绷带，背包带铜碎片和纤维团；整场预算不按尸体倍增。
- 本地真实 ENet 合作及 WSS 专用服务回归均通过，完整功能回归 62 项通过。真实渲染窗口验证鼠标拖动、R 旋转、精确放置和 1024×640 布局。导出包主菜单启动通过；源码测试不能用发行包的 `--script` 参数运行。

## 1. 目标体验

把战后的奖励选择改成发生在战场里的搜刮过程：敌人倒下后留下可交互的尸体，玩家打开尸体或它携带的包，看见格子，等待搜索圆环转完，再逐件发现物品，决定往自己的背包里装什么。

核心循环：**整场战斗胜利 → 点击尸体 → 选择身体或包 → 逐格搜索揭晓 → 比较、装包 → 搜其他尸体或继续探索**。

首版搜刮在整场战斗结束后开放。敌人在战斗中倒下时先留下尸体标记；战斗结束后标记变为可点击。战后画面沿用现有卡牌战场，并保留敌人原来的站位作为尸体位置。

## 2. 玩家操作与画面

### 2.1 战后场景

- 胜利结算后进入“清理战场”；敌人原站位显示倒下的形象或遗骸，悬停提示“搜索小泥团遗骸”“搜索骷髅巡逻兵”。
- 多个敌人对应多个尸体；用边框与简短状态区分“未搜索 / 搜索中 / 尚有物品 / 已搜空”。
- 点击尸体打开搜刮面板，关闭面板回到战后场景。底部保留“继续探索”，离开当前节点前提示放弃未搜索及未取走的物资。

### 2.2 搜刮面板

| 区域 | 内容与操作 |
| --- | --- |
| 左侧：搜索对象 | 尸体名称与形象；身体、武器、护具、腰包、背包等可搜索区域及状态 |
| 中间：现场格子 | 当前区域的格子、未知遮罩、搜索圆环、已经发现的物品；选中已发现物品后显示详情 |
| 右侧：我的携带空间 | 复用胸挂、背包、保险箱及拖拽、旋转、整理、丢弃、捡回功能 |

选择一个区域后自动顺序搜索，无需玩家逐格重复点击。当前搜索格显示圆环，完成后揭晓物品或确认为空。多格物品作为一个整体揭晓，其覆盖格不会重复搜索。已发现的物品可以立即拖入自己的携带空间，搜索继续进行。

未知物品显示统一的中性占格轮廓，按物品实际尺寸合并成一个区块；揭晓前不展示名称、图标、品质颜色、价格或牌效，详情、悬停提示、筛选和排序也不能提前暴露这些信息。区域容量与物品几何可以展示，未知物品不能选择或装包。

### 2.3 节奏建议

- 打开区域的起始动作约 0.3～0.5 秒；发现一件物品约 0.6～1.0 秒；确认空格采用短扫过。
- 普通野怪一次搜索尽量在 2～4 秒内完成；较大的包可以更久，具体随试玩调整格子数量与速度。
- 圆环与搜索声持续反馈进度；揭晓时淡入物品，再出现品质边框与轻提示音。
- 搜索时长按区域规则确定，避免按隐藏品质改变等待时间。
- 同一玩家同时搜索一个区域；切换区域、关闭面板或暂停会中断当前搜索。已揭晓结果保留，当前未完成的那一格下次重新开始。单纯的界面刷新或网络快照不重置圆环。
- 搜索只负责发现物品；拿走物品仍需玩家选择装包。

## 3. 两类敌人的搜刮区别

### 3.1 普通野怪

小泥团、洞穴蝠等先使用一个“身体 / 遗骸”区域，建议 2×3 格，放少量符合敌人身份的材料与偶尔的特殊掉落。具体物品组合须验证真实尺寸能放入源容器。大型矿偶可以使用更大的遗骸区域。

同场多个野怪分别留下遗骸，但整场掉落共用一个收益预算，按敌人身份分配。不能给每具尸体都复制原先整场的完整奖励。

### 3.2 带装备的敌人

增加“骷髅巡逻兵”作为首个完整样例：战斗画面能看见它的武器、护具和携带包，战后搜的是这一只敌人实际携带的物品。

| 搜索区域 | 样例内容 | 建议表现 |
| --- | --- | --- |
| 武器位 | 铜短剑或新的破旧敌人武器 | 能看出持有武器，具体属性搜索后显示 |
| 护具位 | 盾牌、护腕等 | 单独搜索，揭晓后可装包 |
| 腰包 | 少量补给、小材料 | 2×2 格，独立搜索 |
| 背包 | 材料、货物、特殊掉落 | 3×4 格，独立搜索 |

敌人的装备在生成遭遇时固定，并记录到该敌人实例；武器外观、对应攻击意图与掉落保持一致。首个骷髅样例可以用固定配装和对应的固定攻击循环，之后再扩展变体。

首版的腰包与背包承担搜索区域的功能。把敌人的包本身做成可穿戴、可扩容的装备，是后续独立扩展。

## 4. 奖励规则的变化

- 新生成的尸体战利品改为“发现后均可拿取，携带容量限制收益”，取消这些物品上的战斗个人任选一件规则。
- 卡牌继续来自物品：搜索到武器并装包后，由现有物品卡牌系统生成对应卡牌；胸挂、背包、保险箱的入牌回合沿用现有规则。
- 怪物材料、敌人装备、包内物资分别配置来源；整场总价值、装备产出与合作人均收益重新对齐现有基线。掉落预算需在生成敌人配装时约束，不能等胜利后把已经装备的武器随机换掉。
- 同种物品可以掉落多件，每件都有独立 ID；领取按物品实例处理，不能再仅用物品定义 ID 区分。
- 放置失败时，物品继续留在尸体或包内；成功后才从来源移除。品质、剩余使用次数等实例属性随物品转移。
- 本轮先改战斗尸体；宝箱随后可以复用搜索区域与逐格揭晓。采集与事件节点按各自玩法单独处理。

## 5. 数据、恢复与合作

建议把搜索来源存进当前节点的已裁定内容，至少包含：来源 ID、敌人实例 ID、区域 ID、区域尺寸、物品实例 ID、固定布局、已搜索格、已揭晓物品及领取状态。具体字段命名沿用工程现有约定。

物品状态：**未发现 → 搜索中 → 已发现 → 已取走**。每具尸体与每个包有独立状态，切换对象不会串进度。

- 掉落与布局在节点/遭遇首次裁定时固定；关闭重开、恢复局档、重新搜索都不重新抽奖。
- 战斗胜利结算时，先从敌人实例建立尸体记录，再清理战斗状态；结算重复调用不得生成第二份尸体或物品。
- 保存已完成的搜索与领取；恢复时把未完成的搜索转回待搜索。旧局已裁定的节点保留原来的奖励与领取规则，新节点采用新规则，避免重抽或补发。
- 合作时尸体内每件物品全队只有一份；搜索进度与已揭晓结果全队共享。双方可同时搜不同区域，同一区域只允许一位成员搜索，另一位能看到进度；中断或掉线后释放该区域。
- 搜索开始、中断、完成与领取由主机裁定。时间通过可注入的规则时钟判断，UI 圆环只表现进度，客户端不能自行宣布完成或领取未知物品。
- 两人同时领取同一物品，只允许一个事务成功；沿用动作 ID、回执、快照与领取回滚机制。
- 现有主机直接下发完整 run，需要改为成员可见的投影。首次出发、常规快照、重连补发和相关回执都必须过滤隐藏物品信息；原始固定掉落只留在权威状态中。
- 合作离开节点沿用现有推进裁定，并检查另一位成员是否仍在搜索或装包。

## 7. 分阶段实施与验收

| 阶段 | 交付内容 | 验收门槛 |
| --- | --- | --- |
| P1：普通野怪闭环 | 单人战后尸体入口、身体格子、顺序搜索圆环、揭晓、拖拽装包、关闭重开与保存；新尸体取消任选一件 | 打败小泥团与蝠后，能分别点击遗骸；揭晓前看不到详情；装包后来源减少、下一场牌组正确；重开不刷掉落 |
| P2：装备敌人与多个包 | 骷髅巡逻兵、可见配装、武器/护具位、腰包/背包；区域切换与整场收益调整 | 战斗中看到的武器能从对应尸体搜出；不同包独立搜索；同种物品多件领取不串 ID；满包后腾空间能继续拿 |
| P3：合作与完成度 | 主机搜索计时、共享揭晓、区域占用、并发领取、隐藏信息投影、重连恢复、音画与操作打磨 | 两人可搜不同区域；同一物品不能复制领取；客机快照无隐藏详情；掉线重连保留已揭晓/已领取状态；双方能正常继续探索和撤离 |

P1 先验证最关键的“点尸体 → 转圈 → 发现 → 装包”手感。P2 扩展有装备敌人；P3 接入合作后再作为完整搜刮改版交付。首版暂不加入搜索耗体力、随机被打断等额外惩罚，先把搜索反馈和等待节奏做好。

必要验证覆盖：未知物品无法领取、隐藏提示不泄露、空格与多格物品揭晓、多个相同定义物品、当前搜索中断、刷新不重置进度、满包回滚、重复结算、旧局恢复、合作并发与重连。另做真实引擎画面检查，确认尸体点击范围、圆环反馈和小窗口布局。
