## 5. 缺陷详情与复测标准

### F-01　战利品实例 ID 冲突导致撤离后丢物

**复现：**基础套装入胸挂，下洞；在战斗节点领取奖励，再在后续节点领取另一件物品；到撤离点撤离；对照结算清单与农场材料仓库。

**实际：**本次单人局获得纤维团、绷带、绷带，三个条目的 `instance_id` 均为 `1003`；结算的 `next_instance_id` 仍为 `1003`。落盘后仓库仅有 1 件。`apply_settlement()` 按 ID 去重，后两件被跳过。

**定位：**`scripts/domain/expedition_game.gd:342` 的 `run_inventory()`，以及 `:216` 附近的 `member_inventory()`，绑定新建字典，`next_instance_id` 是数值拷贝；`InventoryGame.next_instance_id()` 递增的是包装字典，没有写回局状态。面板每次重新取得库存视图，就重复使用同一编号。

**影响：**正常获得不同战利品也会丢失；后续分配 ID 还可能再次撞上已经入库的物品，影响配装、来源牌和结算对账。

**建议与复测：**统一在局状态持有并递增实例编号；单人、双人、分享、拾取使用同一分配边界。验证连续领取 3 件不同物品的 ID 唯一，恢复后继续领取仍唯一，撤离前后数量/类型/使用次数逐件一致，重复应用同一结算不会增加或减少库存。

证据：[完整单人流程日志](2026-10-02/solo_probe.txt)。

### F-02　同一奖励可反复领取

**复现：**赢得一场普通战斗；点某个候选的“放入背包”；再次点同一候选。

**实际：**专项中同一纤维团数量由 `0→1→2`，候选列表仍为 `["fiber_clump"]`。普通战斗选择后重设为 `[def_id]`，没有消费掉奖励；采集等非二选一奖励路径也没有移除已领条目。

**定位：**`scripts/ui/expedition_map_panel.gd:369` 的 `_on_claim_reward()`；`InventoryGame.claim_reward()` 只负责创建/放置实例，不能限制节点奖励领取次数。

**建议与复测：**节点奖励在规则层完成“校验候选→成功放置→消费奖励”事务；满包时保持候选，放置成功后移除或标记已领取。验证普通战斗只能二选一一次，采集每条奖励各一次，连续点击、读档和失败重试不能复制。不要仅隐藏按钮，因为还有状态恢复路径。

证据：[场景复现日志](2026-10-02/runtime_probe.txt)、[连续领取后的画面](2026-10-02/reward_after_twice.png)。

### F-03　合作出发流程未接通

**复现：**主机创建房间，客机连接 `127.0.0.1`，双方准备，主机点击出发。

**实际：**链路连接成功，房间有 2 名成员；双方都有待确认局 ID，但等待 2 秒后主机尚未开局，双方出发信号均未触发。专项手动调用缺失的 `client.confirm_depart()` 后，主机才开局，客机拿到镜像，但客机界面切换信号仍未触发。

**定位：**`scripts/ui/room_panel.gd` 未调用 `confirm_depart()`，`_on_client_depart()` 也未连接 `client.run_received`。`SessionClient` 收到 `depart_begin` 仅存入 `pending_run_id`。现有会话测试直接调用确认接口，绕过了实际 UI 缺口。

**建议与复测：**在收到出发请求后完成客机保存与回执，并在正式局快照到达后切换客机界面；保存失败必须阻止开局并提示原因。用两个独立进程的真实房间按钮完成建房、加入、准备、取消、出发，禁止测试脚本代替 UI 调用出发确认。

证据：[场景复现日志中的 QA_ROOM_DEPART / QA_MANUAL_CONFIRM](2026-10-02/runtime_probe.txt)、[等待中的客机房间](2026-10-02/coop_depart_waiting.png)。

### F-04　合作局地图与战斗操作未形成可玩闭环

**复现：**在专项中补上 F-03 的缺失确认，打开主机现用地图面板；主机选择第一排，客机不投票。

**实际：**主机局位置 `0→1`，客机镜像仍为第 0 排。`ExpeditionMapPanel._on_move()` 直接调用单人式 `expedition.move_to()`，没有经过 `SessionHost.host_action("vote_move", ...)`。

**关联缺口（代码确认，双机体验未验证）：**`CoopClientPanel` 只有固定列 0 的前进、领取、撤离、放弃和信号按钮，没有手牌出牌、目标选择、结束回合、救援及分享界面；其战斗文案也写着“出牌由主机界面或测试入口裁定”。`BattleScreen` 固定操作 `p1`，结束回合后会等待其他可行动玩家。现有规则能够处理 `p2` 指令，但产品 UI 没有提供完整操作链路。

**建议与复测：**主机、客机所有合作动作接入同一会话裁定入口；提供两边可实际使用的地图、手牌、目标、结束回合及分配操作。验证一人投票不前进，双方同票才前进，镜像更新一致；双方都能独立出牌和结束回合，完成战斗、分配和共同撤离。

证据：[QA_HOST_MAP_BYPASS](2026-10-02/runtime_probe.txt)；代码见 `scripts/ui/expedition_map_panel.gd:333`、`scripts/ui/coop_client_panel.gd`、`scripts/ui/battle_screen.gd:232`。

### F-05　萤果缺少场景模型映射

**复现：**获得萤果种子后播种，或载入存在萤果地块的存档。

**实际：**规则播种返回成功，但 `_refresh_plot_model()` 报 `Invalid access to property or key 'glow_berry'`。地块种类为萤果，模型键仍为 `empty`；每秒生长刷新还会再次触发同一异常。

**定位：**`scripts/world/farm_world.gd:20` 的 `STAGE_MODELS` 仅有白菜、胡萝卜、岩芽菜；`:402` 直接访问 `STAGE_MODELS[kind][stage]`。`d28_content_smoke.gd` 只测种植规则，不实例化农场场景。

**建议与复测：**为萤果补全萌芽、生长、成熟映射；缺素材时先给可用占位与兜底。验证四种植物在所有生长阶段、重启载入、成熟标记和收获过程均无场景脚本异常。

证据：[运行异常日志](2026-10-02/runtime_probe.txt)、[播种后仍是空地](2026-10-02/glow_berry_missing_model.png)。

### F-06　浇水回归假通过

**复现：**运行 `tests/stage2_rules_smoke.gd`。

**实际：**`:143` 访问 `result["segment"]` 报错，随后仍输出 `STAGE2_RULES_PASS` 且退出码 0。当前 `FarmGame.water()` 返回 `watered/skipped`，没有 `segment` 字段；后续边界断言被异常中断，不能视为已执行通过。

**建议与复测：**按当前接口检查地块实际 `watered_segments` 与拒绝结果；回归收集器同时检查未预期 `SCRIPT ERROR`，不能只用退出码或 PASS 字符串判定。验证时段边界、重复浇水、成熟拒绝和二级水壶批量作用；人为制造字段错误时整套验收必须失败。

证据：[本次浇水回归输出](2026-10-02/stage2_rules_smoke.txt)。

### F-07　新面板按钮文字对比度过低

**复现：**打开战备箱、洞窟入口、合作房间或战斗界面。

**实际：**可操作按钮也是浅色字配浅奶油/浅绿背景，物品名称、领取、返回、结束行动等难以辨认。专项读取启用按钮的字体色为 `(0.875,0.875,0.875,1)`，背景约 `(0.910,0.941,0.847,1)`。

**复测：**默认窗口下无需猜测即可读出物品、领取、配装、出牌、返回等文案；启用与禁用状态清楚区分。

### F-08　播种引导展示与存档落后

**复现：**新档按第一步播种成功，不进行其他会保存的操作，观察提示并退出重开。

**实际：**播种后内存 `tutorial_step=1`，磁盘仍为 `0`，横幅仍显示第一步。手动浇水后才刷新到第三步。原因是播种处理器先 `_save()`、`_refresh_all()`，再 `_advance_tutorial(0)`；“跳过引导”同样只改内存并隐藏面板，没有立即保存。

**建议与复测：**成功动作先推进引导，再统一保存和刷新；跳过也保存。每一步成功后即刻显示下一步，退出重开保持，不能要求再做一次无关操作。

证据：[QA_TUTORIAL](2026-10-02/runtime_probe.txt)、[播种后的横幅](2026-10-02/tutorial_after_plant.png)；定位 `scripts/world/farm_world.gd:527`、`scripts/ui/farm_hud.gd:297`。

### F-11　客机无法取消准备

**复现：**客机加入后连续点两次“准备／取消准备”。

**实际：**第二次点击仍为准备状态，专项记录 `ready_after_two_clicks=true`。`RoomPanel._on_ready()` 客机分支固定调用 `client.set_ready(true)`，没有切换，也没有刷新成员列表展示。

**建议与复测：**依据主机确认的成员准备状态切换请求并更新界面；客机取消后主机不得出发，再次准备后可出发。

### F-12　网络探针错误轮询

**复现：**运行 `tests/d21_net_probe.gd`。

**实际：**`client.close()` 后循环调用 `client.poll()`，产生 50 次 `The multiplayer instance isn't currently active`，但脚本输出 PASS。往返与断开断言本身成功，此处是测试工具缺陷，不能据此断言游戏联网失效。

**建议与复测：**关闭后只等待/查询连接状态，停止轮询 inactive peer；联网探针应无未预期错误，并继续验证连接、往返和主动断开。

证据：[本次网络探针输出](2026-10-02/d21_net_probe.txt)，定位 `tests/d21_net_probe.gd:37`。

### F-13　地图顶栏在默认窗口布局异常
