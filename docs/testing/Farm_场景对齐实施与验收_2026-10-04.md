## 三种验收结果

**实际操作**：`capture_scene_alignment.gd` 120 项检查通过。使用 Godot 视口鼠标事件测试建筑、石阶、装备台、具体客人、门窗、院门、留言板、主人、展示架、地块及装备拖放；还验证报价对应的金币增量、只读操作不改自家状态、十次拜访往返、二十轮快速切景和 ESC 关闭优先级。另有尺寸与按钮边界检查。

**洞内操作与展示**：`capture_expedition_redesign.gd` 通过，生成 16 张截图；真实选牌、点目标、拖牌、快捷键、牌堆／记录弹窗、节点确认、搜刮与撤离路径通过。`scene_workspace_smoke.gd` 的展示夹具检查线上及合作客机的选择／确认边界、等待到账与已到账、地址簿过滤和房间状态，窗口运行 44 项检查通过。完整运行结果见 [verification.json](../../screenshots/scene_alignment_2026-10-04/verification.json)。

**功能回归**：完整 headless 回归 **61 项通过、0 项失败**，结果记录在 [regression.txt](../../screenshots/scene_alignment_2026-10-04/regression.txt)。收集器要求退出码为 0、无未预期 ERROR、无 SCRIPT ERROR；既有主动损坏 JSON 和 dummy 音频退出提示沿用限定白名单。本地 WSS 测试使用隔离证书和测试数据库，覆盖实际请求、资产隔离和拜访只读路径。真实 ENet 合作 UI 回归覆盖双票前进、双方独立出牌／结束回合、各自领取、共同撤离与客机结算；旧“直接点列号”的测试同步为“选择节点→确认投票”，保留原裁定和资产断言。

**画面检查**：当前画面覆盖农场、全部生活工作区、商店三客报价、营地、队员状态、院子、小屋同一院子窗口、菜单／登录／设置、三层洞窟、路线／投票、卡牌战场和结算。与实施前画面对照，检查了入口遮挡、地面边界、相机、人物尺度、字号及工作区范围。图片为真实引擎输出，未后期拼接或替换。

## 数据来源与边界

参观快照新增 `online`、默认 `appearance`／`roof_color`、空 `welcome_message` 和 `snapshot_read_at`；时间表示服务端读取快照的时间。未新增玩家装修或留言编辑能力，未配置时明确展示默认内容。头像为静态形象，在线状态不代表实时角色位置。

标为 `fixture` 的队员、线上路线、投票、结算和地址簿图片使用构造的内存快照；证明展示和意图边界，不能替代公网真人双机验收。公网部署、两台真实电脑与真人合作仍沿既有项目记录待验收。

运行检查使用独立项目名与存档目录，没有启动原项目写入真实玩家存档；生产证书、线上数据库和主项目 checkout 未改动。经济数值、战斗规则、资产事务与线上权威流程沿用原实现。

## 维护与运行

世界造型维护 `scene_art.gd`，交互与常驻规则上下文仍在 `farm_world.gd`。生活主题在 `life_ui.gd`；洞内主题、节点预览、结算和实际格子各为独立组件。四种新增 SVG 图标登记在 `assets/stage1_manifest.json`。

在本 worktree 先用 Godot 导入 `project.godot`，再按 F5 或运行项目。原来的 `build/Farm.exe` 是旧导出包；本次交付为源码与截图，没有重打包或部署服务端。

截图类脚本需要真实渲染窗口；请在另存的、独立项目名的副本中运行 `capture_scene_alignment.gd`，该脚本会创建测试农场。规则回归仍使用 `tests/run_regression.ps1`。
