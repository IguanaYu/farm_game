## 0. 给 AI 的操作规程（先读，防幻觉防误判）

1. **数值断言以文件为权威，不以 OCR 为准**：金币/作物/教程步等一律查 `user://` 存档或服务器 SQLite（路径见 §2.6），截图只用于布局/存在性判断。
2. **截图核验用中立转录**：对截图提问必须是"逐字转录画面上的文字与描述各区域内容"，禁止引导性问题（"是不是有商店？"会催生幻觉）。同一结论需两帧截图一致才记录 PASS。
3. **后台窗口收不到键盘事件**：键盘输入（房号、昵称）只对前台窗口有效。多窗时先前置目标窗口再敲键。
4. **点击定位用像素颜色扫描**：优先按颜色特征（金黄 `#ffd257` 系按钮、绿色 `#87b06f` 系）扫描定位按钮中心，不要估算坐标。游戏窗口标题为 **"小小农场"**。
5. **锁屏应对**：检测到锁屏时改用 PrintWindow+PostMessage 管线截图与点击，坐标补偿 **(+12, +40)**；无法补偿时暂停等用户。
6. **每项测试后取证**：截图存 `screenshots/live_r0r7_YYYYMMDD/T编号_N.png`，结论记入缺陷表（§7）。
7. **不确定即标记**：视觉判定拿不准的写 `UNCERTAIN` 附截图，不要硬填 PASS。
8. **破坏性操作前置确认**：强杀进程/删档/维护开关会影响同机其他窗口，执行前确认没有未取证的进行中测试。

## 2. 环境准备

### 2.1 构建
- 客户端：`build/Farm.exe`（若代码有更新先重导出：`Godot --headless --path . --export-release "Windows Desktop" build/Farm.exe`）。
- 服务器：直接用同一 Godot 可执行跑 `res://scenes/server_main.tscn`（无需导出）。

### 2.2 本地测试服务器（重要：生产服务器仍是 PROTO 2，新客户端连它必被拒！）
```bash
Godot_v4.6.1-stable_win64_console.exe --headless --path . res://scenes/server_main.tscn -- \
  --port 31980 --db .zcode/live/run/live_test.db \
  --cert server/secrets/farm_server.crt --key server/secrets/farm_server.key --tag live
```
- 证书已验证与客户端钉扎证书（`client/certs/farm_server.crt`）一致，可直接互通。
- 库文件放 `.zcode/live/run/`（已 gitignore），**每次开新测试日建议删库重开**（见 §6.OPS-5 备份演练例外）。

### 2.3 测试账户（邀请码）
```bash
# 同一命令行加 --new-invite 3 --invite-note live 即打印 3 个邀请码后退出
```
需要 ≥2 个账户（甲=窗口A、乙=窗口B）。两人都激活后各自点"一键登录"可续用。

### 2.4 客户端指向本地服
登录面板有**服务器地址输入框**（默认是生产地址 `wss://111.229.19.23:31971`）→ 改成 `wss://127.0.0.1:31980` 再激活/登录。

### 2.5 双开布局
- 两个 `Farm.exe` 进程可同时运行（窗口同标题"小小农场"，按屏幕左/右半区摆放区分：甲=左，乙=右）。
- **注意**：两实例共享 `user://`——`session.json` 存最后一次登录的 token。双开不同账户没问题（各自内存持有 token），但**不要中途重启其中一个后依赖旧 session**：重启的那个要在登录面板重新输地址+登录对应账户。
- 建议 1440×900 窗口；窄窗行为另设 P2 专项（T-POL-6）。

### 2.6 数值权威来源
- 线上档：服务器库 `.zcode/live/run/live_test.db`（accounts.farm_state；健康/状态可用 §6 命令）。
- 本机档（单机模式）：`%APPDATA%/Godot/app_userdata/小小农场/farm_save_v1.json`。

## 3. P0 冒烟（必须全过，约 20 分钟）

### T-A01 启动与主菜单
启动 Farm.exe → 出现主菜单（标题、开始/联机/设置可见）。截图两帧核验。

### T-A02 单机进农场（R2 上下文 + R3 环境总检）
"开始新游戏"（或继续）→ 进入农场。逐项核验：
- **连续地形**：四边看不到地台截面/大片纯色空隙，地面延伸到画面外（对照旧版"悬浮盒子"）。
- **林带与远山**：画面周围有一圈树 + 远处山影轮廓。
- **入口实体化**：商店门前有**绿白条纹雨棚+菜筐**；东南有**灰色石阶+发光提灯**；西侧有**蓝色溪流+石桥+红色信箱（金黄小旗）**。
- **待开垦地**：未购买的地块显示为**低矮绿色草桩**（不再是空洞）。
- 金币/作物状态记录为基线（读存档）。

### T-A03 场景切换零重建（R2 核心）
点商店门廊（或商店建筑）→ **0.2~0.35s 淡入过渡** → 商店内景。核验：
- 暖木地板、后墙、**后柜台（金黄沿）**、左右**分层货架（上面摆货）**、角落委托台。
- **三位客人在前景并排站**，且与当日集市里的三位客人形象一致。
- 商店**自己的相机角度**（比农场更低更近）。
- 点**门**回农场：过渡正常、农场相机还原、**金币/作物/成熟标记与进店前完全一致**（读档比对）。
- 重复往返 3 次再比对一次（十次版已由 d47 自动覆盖，实机 3 次足够）。

### T-A04 商店交易不退出场景
在店内：点柜台 → 商店面板 → 买 1 组种子 → 面板收起后**人还在商店**；点任一客人 → 集市面板 → 卖一批作物 → 仍在商店。金币变化读档核对。

### T-A05 洞口营地（R4）
农场点**上山石阶** → 切换到营地：
- **山壁+暗色洞口**（冷光沿）、**篝火（火焰在闪）**、战备台、帐篷、下山路口（石板+路灯）。
- 点**洞口** → 出发界面（营地介绍/牌组/出发按钮）。
- 点**篝火** → 房间页（单机=局域网房间面板；线上见 T-C 组）。
- 点**战备台** → 配装面板，正常关闭。
- 点**下山路口** → 回农场。

### T-A06 单人探险全链路（离线）
战备领取基础套装入胸挂 → 洞口 → 出发 → 地图 → 选路进战斗节点 → 打赢（基础牌组打小泥团）→ 搜刮领取 → 连走到第 4 排休整点 → 撤离 → 结算画面 → 确认回家 → **回到洞口营地**（不是农场！）→ 下山回农场。装备返还读档核对。

### T-A07 线上登录（M3）
登录面板输本地地址 + 邀请码激活 → 进线上农场 → 右上角在线角标"已连接"。农场基本操作（播种/浇水）正常且金币变化**以服务器库为准**。

### T-A08 拜访冒烟（R7，需 T-C 前置乙账户）
甲在线上农场点**信箱** → 邻里地址簿 → 乙条目（在线·开放参观）→ 去拜访 → 乙的院子：
- 院子是乙的农场快照（地块状态只读展示）、有**房子（红顶）**与**花藤院门**。
- 点房子 → 小屋：主人形象、茶桌、留言板；**点留言板 → 显示"【玩家乙的留言】…"**。
- 点门或窗 → 回院子；点**花藤院门** → 回自己农场，提示"回到了自己的农场"。
- **红线**：拜访期间甲的任何农场操作被拦（提示"拜访中不能操作"）。

## 4. P1 双人线上全流程（核心，双窗操作，约 40 分钟）

> 操作顺序提示：所有键盘输入先前置目标窗口。甲=左窗（房主），乙=右窗。

### T-C01 建房加入
甲篝火 → 创建房间 → **房号显示 6 位**；乙篝火 → 输入房号加入 → 两窗成员列表实时同步（push 推送）。

### T-C02 准备与出发事务
乙先准备、甲未准备时点发起出发 → **被拒"还有成员未准备（玩家甲）"**；甲也准备 → 发起出发 → 双方同时进入同一局（开局面板/提示一致）。

### T-C03 双人推图与战斗
- 双方投票选路（同票前进，**不同票时顶栏显示各自投票**）。
- 进战斗节点 → 任一方发起战斗 → 双方战斗界面打开（p2 视角正确）→ **各自出牌/结束回合**（轮到谁的提示）→ 打赢 → 双方都进搜刮。
- 搜刮：各领各的（二选一锁定语义）；公共物资一方领走后另一方列表消失。

### T-C04 共同撤离与结算对账
走到第 4 排 → 休整 → **双票撤离** → 双方结算画面 → 确认后：
- 双方**各自回营地**；装备返还/获得物逐件与局内拾取一致（以两个账户的服务器库核对）。
- 结算后重开篝火可再建新局（占用已清）。

### T-C05 掉线暂停语义（S06）
任一节点：直接关闭乙进程 → 甲做任意局内动作 → 被拒"有成员掉线：本局暂停推进…"；乙重启客户端 → 登录（同地址同账户）→ **自动回到房间与局面板**（welcome 恢复）→ 甲动作恢复可用。

### T-C06 强杀服务器续局（S07）
战斗中：杀服务器进程（taskkill）→ 重启同参数服务器 → 双方等待自动重连（角标"重连中→已连接"）→ 局恢复同位置 → 继续打到撤离。**重点核验：重启前后手牌/血量/进度一致、结算不重复入账。**

### T-C07 快捷信号与分享
战斗/节点内发快捷信号（建议撤离）→ 对方可见；分享流程：提出→对方接受→物品转移（容量不足时提示且物品留原主）。

## 5. P2 深度与打磨项

### T-POL-1 地点 BGM（R5）
进农场/商店/营地分别听背景音乐是否**换曲**（farm→shop→camp 三曲不同；商店暖、营地夜）。AI 只能确认"切换时音乐有变化"，好不好听留给用户。
### T-POL-2 作物新模型
种岩芽菜/萤果 → 三阶段形态变化（萤果成熟**发光、浆果 3 颗**），不再长得像胡萝卜。
### T-POL-3 客人与篝火动效
店内客人轻微起伏；营地篝火火焰闪烁。
### T-POL-4 ESC 与面板层级
各场景按 ESC：有面板时先关面板，无面板时出暂停菜单；商店/营地/拜访中行为一致。
### T-POL-5 未开放拜访入口（单机）
单机模式点信箱 → 提示"好友拜访是联机玩法…"（不崩、不进地址簿）。
### T-POL-6 窄窗重排
窗口拉到 1024×640：HUD/面板不越界、文字不缩到不可读（对照设计稿 §8 约束）。
### T-POL-7 教程全流程（线上）
新账户 0→1→2→3→4→99 推进顺滑（播种→浇水→收获→卖菜→再播种），提示位置合理。

### T-USER-1~3（只能用户验收，AI 不判）
- 音乐/音效主观感受；操作手感与点击热区舒适度；三人短话气泡可读性（本轮未做气泡 UI，客人短话为已知缺口，见路线图打磨轮偏差）。

## 6. 服务器运维项（AI 可全自动，无需游戏窗口）

### T-OPS-1 健康检查
`ping` 命令（或 curl websocket）→ 健康包含 online/rooms/active_runs/errors/uptime。
### T-OPS-2 状态子命令
`--db <库> --status` → `STATUS_OK {accounts…}`。
### T-OPS-3 备份与恢复演练
`--backup <dir>` → 生成快照 → 用另一 Godot 实例 `--db <快照> --status` 打开核对账户数。
### T-OPS-4 维护门控
`touch maintenance.flag` → 在线客户端收"维护"提示并断开、新登录被拒；删文件后恢复登录。**注意恢复后客户端要重新登录。**
### T-OPS-5 日志观察
跑完全部测试后查服务器控制台：无成片 internal_error/tx_failed；错误计数（健康包）为 0 或有解释。
