# 2.7 进度保存与异常恢复：详细设计 v0.1

日期：2026-10-01。状态：产品与一致性设计，尚未实现。[设计索引](第二大阶段详细设计索引.md)；出发和结算见 [2.4](Godot_阶段2.4_单人洞窟与撤离闭环_详细设计_v0.1.md)，队伍规则见 [2.6](Godot_阶段2.6_双人合作与战利品分配_详细设计_v0.1.md)。本文规定保存、断线和恢复的结果，不规定底层文件、数据库、通信和代码实现。

## 1. 体验目标与原则

玩家关闭或掉线后，应知道本局是否暂停、哪些物品仍被占用、怎样继续。出现失败时，游戏不靠重新送装备或重新抽奖励掩盖状态错误。

核心原则：已确认操作可以恢复；未确认操作不冒充成功；重复请求只产生一次结果；暂停不发撤离收益；个人农场进度与本局进度分别保存，恢复本局不回滚后来在农场的种植和交易。

首版为本地农场与好友主机合作，不承诺跨设备云同步、自动换主机或抵抗恶意修改本地档。正常掉线和误操作仍须可靠处理。

## 2. 功能 D2.7-01：保存反馈与恢复入口

通常保存自动完成，界面不要求玩家每出一张牌手动存档。重要变更包括出发、出牌、拾取、分享、节点选择、撤离／失败和农场结算。

玩家看见操作成功时，该结果应已有可恢复记录。若保存没有完成，显示“正在确认”或“保存未完成”，不能先显示获得稀有物品再关闭后消失。

主菜单和农场入口列“继续探险”，显示模式、原队友、层数、节点、生命、暂停原因和最后已确认状态。等待结算的局显示“完成结算”，不能误进新的一局。

暂停后仍可使用农场未占用资产，但不能改活动局持有的物品；界面提供“查看占用清单”和“为什么不能出售”解释。

## 3. 功能 D2.7-02：玩家可理解的状态

| 状态 | 界面说明 | 允许操作 |
| --- | --- | --- |
| 未出发 | 在农场准备 | 正常整理、出售、加入房间 |
| 出发确认中 | 等待所有人确认带入物品 | 取消或等待；不开始战斗 |
| 探险中 | 当前局正常进行 | 对应节点允许的操作 |
| 暂停等待队友 | A 掉线，当前局已暂停 | 看状态、等待、保存结束会话 |
| 原主机不在线 | 本局需原主机恢复 | 查看凭据和占用，回农场处理其他资产 |
| 结算等待保存 | 结果已确定，个人存档尚未完成 | 重试保存、看结算；不重复探险 |
| 已结束 | 撤离、死亡或放弃结果已应用 | 整理农场，正常开始新局 |
| 记录异常 | 无法可靠确定当前状态 | 尝试备份恢复、查看信息，不静默删局 |

“暂停”会保留具体回合、手牌、敌人意图、布局、奖励和已完成选择。它不是重新从节点入口开始。

## 4. 功能 D2.7-03：单人关闭与恢复

正常关闭／返回农场暂停时，保存最后已确认局状态；下次点击继续从原位置恢复。战斗中退出不是判失败，也不能重抽牌或重新生成敌人。

强制关闭发生在一张牌处理中：恢复到整张有效牌已完成或完全未发生的边界，不出现能量扣了却没伤害、敌人死了却未结算的半个结果。详情可显示最后动作，帮助玩家核对。

主动放弃单独展示未保护物品损失清单，确认后按失败结算。未完成结算不能因为反复按放弃而重复失去物品。

若玩家在暂停期间回农场卖了白菜，再恢复探险，这笔卖菜仍在。恢复局只还原洞窟状态，不用出发时的整个农场快照覆盖当前档。

## 5. 功能 D2.7-04：客户端断线与重连

任一客户端断线后暂停全局推进，已确认动作保留；未确认点击取消或保持待确认，恢复时明确结果。画面显示掉线成员和 120 秒初始等待时长。

等待期间可看手牌、物品和日志，不可出牌、领货或切节点。掉线者回到游戏时，通过原局身份和会话凭据恢复，不能只输入同名昵称冒充原成员。

重连后展示恢复摘要，例如“已恢复到第 3 回合，最近一张切击已生效”，双方确认当前状态可继续。只重播必要提示，不把所有历史动画长篇重新播放。

120 秒过后提供“保存暂停并结束本次连接”。超时本身不判死亡、撤离或赠送物品。日后原队伍可恢复；目前首版不加入自动托管和新成员替补。

## 6. 功能 D2.7-05：主机关闭与全队恢复

主机正常结束会话，保存本局，并提示队友“本局已暂停，等待原主机下次恢复”。主机崩溃时客户端保留已确认状态及自己的物品占用，原主机重新打开后提供恢复。

恢复合作局需要同规则版本、同原成员或已结算离开的成员记录。首版不自动迁移主机；新朋友不能冒充掉线队友进入同一局并拿旧物品。

原主机一直不可达时，客户端可以继续经营其他农场资产，但不能擅自把本局占用物全部返还又保留局内收益。界面说明需原局记录恢复；这是本地好友主机方案的实际限制。

主机个人放弃后若队友仍继续，原主机可在农场画面维持会话。关闭整个程序则暂停剩余者，不强制剩余者失败。全队放弃需要双方确认，防止用退出代替队友的资产损失决定。

## 7. 功能 D2.7-06：出发、携带与结算的一致性

每局有唯一身份，每人有实际带入清单，结果有唯一结算身份。玩家不需看到内部编号，但恢复详情可以复制诊断信息。

出发分为准备、个人占用确认、全队正式开始。准备没有完成时，安全撤销占用并留在农场；已经正式开始时恢复活动局。不可在同一台机器误判“没开始”退回装备，同时另一台已经打完战斗。

结算包含未损失带入物返还、新增物获得、补给消耗、丢弃／分享后的归属和失败损失。对同一结算再次收到只确认已处理，不重发、不重复扣。

个人档在一次已确认结果中登记哪些结算已应用。客户端保存失败，主机保留待确认结果供重试；客户端成功但确认消息丢失，重发后识别已应用，再回确认。

同一件带入物被分享给队友：原主人结算为转出，接收者按当前持有结算；不能同时返还原主人又给接收者。接收者失败时，物品按其保护状态损失，不自动回原主人。

## 8. 功能 D2.7-07：存档损坏与旧档升级

当前农场档内容版本为 v5。新增探险信息时，旧金币、种子词条、作物批次、地块拥有状态、经验、市场锁定与育种机进度完整保留。老档升级不能强迫重开。

旧档没有洞窟信息时按“未解锁／未出发”建立入口，而不是捏造已完成目标。新档和升级老档获得基础装备机会相同，但同一档不能重复领多套。

主记录损坏可读取最近完整备份，并清楚提示恢复时间及可能未包含的最新操作。个人档和局档的版本必须核对，不能用旧备份的带入清单覆盖已经入档的新结算。

主记录和备份都不可用时保留原文件并提供说明，不能悄悄新建零金币档。恢复失败时玩家可复制诊断信息给后续开发对话；游戏不输出全部个人库存到公开聊天服务。

来自未来或不兼容规则版本的局，提示使用对应版本恢复，不能用缺失字段假设结算成功。首版不提供未知版本通用转换器。

## 9. 功能 D2.7-08：故障场景表

| 发生位置 | 故障 | 预期恢复 |
| --- | --- | --- |
| 房间准备 | 一人退出 | 没有正式出发，不扣物 |
| 出发确认 | 一端已占用另一端失败 | 根据正式开始记录恢复或整体撤销，不猜测 |
| 出牌 | 确认消息丢失 | 重连后看到已生效或未生效，最多一次费用 |
| 公共拾取 | 两人同点后断线 | 唯一主人保留，公共区不会重新生成该件 |
| 分享提议 | 接收前掉线 | 提议取消，物品留原主人 |
| 分享确认 | 移交后确认丢失 | 恢复已完成归属，不能双方都拿 |
| 打开宝箱 | 程序关闭 | 原候选与已领取状态恢复，不重抽 |
| 撤离决定 | 一人刚确认后掉线 | 保留选择，若未形成共同结算则等待恢复 |
| 结果确定 | 客户端写盘失败 | 固定结果保留，重试同一结算 |
| 结果已保存 | 主机没收到确认 | 重发仅回确认，不再加物品 |
| 仓库满 | 关闭结算界面 | 产物在待领取区，当前局可以完成 |
| 回农场暂停 | 玩家卖了未带入作物 | 恢复局不回滚这笔交易 |

## 10. 功能 D2.7-09：提示文案与可操作性

短暂等待：“正在确认拾取，请稍候。”断线：“阿禾已断开，本局暂停。已确认的物品和行动会保留。”结果未保存：“撤离结果已确定，但本地保存未完成。请重试保存。”

保存未完成状态提供重试和退出并保留记录，不显示“安全保存成功”。不要给玩家内部网络错误码作唯一解释；详情页可供开发诊断。

继续旧局时显示要恢复的具体局，不自动载入一个玩家以为早已结束的备用局。已经结束的局只能看记录，不能重新开始领取。

## 11. 设计验证关口

分别在出发、出牌、分享、领取、撤离和写盘附近中断，核对个人资产、局内归属和结果。必须能给出明确的状态解释，而不只是“看起来都还在”。

通过条件：同一操作最多影响资产一次；已经确认的奖励可恢复；无法判定时保留未决而不造新结果；旧农场不被局恢复覆盖。

需要继续验证的限制是原主机长期不可达的体验，未来可考虑可靠中继／局记录服务或主机迁移。此类服务设计另立执行方案，首版文案必须如实说明当前能力。
