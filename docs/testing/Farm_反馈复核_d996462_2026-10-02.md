## 3. 需要重新打开的反馈

### 3.1 F-03：占用落盘失败，但成功回执已经发出（P1）

定位：`scripts/ui/room_panel.gd:402`、`scripts/services/session_client.gd:132`。

现有顺序是：第一次 `_save_farm()` → `client.confirm_depart()` 写内存占用并发送 `depart_saved` → 第二次 `_save_farm()` 保存占用状态。第二次保存失败时，面板仅显示警告并返回；主机已经收到成功回执，可以开局。

本次新增面板子类，仅将第二次 `_save_farm()` 注入为失败，其他建房、加入、准备、出发仍走面板处理器，经 `127.0.0.1` 通信。没有代调 `confirm_depart()`，没有修改会话逻辑。实际输出：

```text
save_calls=2 host_started=true
status=警告：占用已写入但落盘失败；重启后可能需要重新占用，请联系主机。
```

这是保存失败路径的确定复现，可能造成重启后农场磁盘档缺少已开局资产占用，违反原反馈“保存失败必须阻止开局”的标准。现有 d31 的 `fail_save=true` 会使**第一次**保存直接失败，因此覆盖不到这条路径。

关闭标准：将占用准备、实际落盘和发送成功回执分开；只有占用状态落盘成功才能发回执。失败时拒绝出发并按事务规则恢复状态，保留可重试行为。增加“第一次成功、第二次失败”的测试，确认双端不开局、客机不切局界面，失败后可重试。

证据与复现脚本：[日志](recheck_d996462/second_save_failure.txt)、[脚本](recheck_d996462/qa_second_save_failure.gd.txt)。脚本使用保存函数替身，是故障注入验证，不是对物理磁盘故障的实测。

### 3.2 F-06：错误白名单只比数量，仍有假通过（P1，验收可信度）

定位：`tests/run_regression.ps1:11`、`:22`、`:25`。

收集器给 `stage6_regression_smoke.gd` 允许 3 条错误，但没有检查这些错误是否为指定的 JSON 解析故障，也没有将 `SCRIPT ERROR` 单独判为失败。因此这个测试出现 1～3 条无关错误时仍会被判通过。

本次在独立小项目中复制原收集器，放入同名的最小测试：子函数访问不存在的字典键触发 `SCRIPT ERROR`，调用者仍输出 PASS 并退出 0。**这是收集器负向测试，不是修改或指称当前 stage6 测试有同样异常。**实际运行原收集器得到：

```text
stage6_regression_smoke.gd  exit=0 errors=1 allow=3 ok
总计 1 项，失败 0 项
REGRESSION_ALL_PASS
```

关闭标准：任何 `SCRIPT ERROR` 都失败；对白名单按预期错误内容／来源匹配，而非错误总数。补充这个负向测试，要求收集器退出非 0。本次现有 44 项的通过结论已人工核对完整错误日志，不依赖这一宽松白名单。

证据：[注入脚本](recheck_d996462/qa_collector_injected.gd.txt)、[异常输出](recheck_d996462/collector_injected_script_error.txt)、[收集器误判](recheck_d996462/collector_false_pass.txt)。
