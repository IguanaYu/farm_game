## 2. 验收对照（总计划 §10-2.4）

| 验收项 | 结果 | 证据 |
| --- | --- | --- |
| 提前撤离也得到合法收益 | 通过 | run_smoke：撤离结算 returned≥3＋gained≥1，占用解除 |
| 死亡只保留允许保护的物品 | 通过 | settle_smoke：保险箱种子保留、未保护清除、耗尽药水不列损失且农场侧同步清除 |
| 重复回家不重复发装备 | 通过 | 返还＝释放占用（农场 loadout 原实例不动）；幂等重放 only-duplicate |
| 关闭重启恢复同一地图和奖励 | 通过 | recovery_sim：局档/农场档重载→同一奖励数组、同一手牌与意图 |
| 满仓可安全结束本局 | 部分简化 | 获得物直接入农场仓库（2.4 未设装备仓库容量上限）；待领取区随 2.5 仓库上线后启用 |
| 强制关闭发生在出发与结算中间仍可恢复 | 通过 | recovery_sim：战斗中强退→恢复→打完→撤离→结算应用 |

设计 §9 回家算例逐条落进 settle_smoke；试玩关口 A（轻装/带货/满载三条路线）待 2.9 实机试玩记录。

## 3. 实施记录与偏差

1. **结算五组对账**：returned（带入释放占用）/gained（新实例入库）/protected（保险箱）/lost（从农场清除）/consumed（耗尽，农场侧移除）。局内新物品沿用局内 ID（占用期间农场发号器冻结，无冲突），结算同步 `next_instance_id`。
2. **公共区**：节点内丢弃/捡回闭环（`node_drops`）；离开节点即放弃，不可回头。
3. **休整多抽**以 `CombatGame.draw_extra` 落地，用后清标志。
4. **地图揭示策略**：固定图全排类型可见（具体敌人/事件选项/掉落进节点才揭示），符合设计 §3"已揭示的节点类型可见"。
5. 计划 §6 待澄清项现状：#3（第 4 排先二选一才出现撤离）按设计实现（休整确认后撤离/深入按钮并存）；#5"返回农场并暂停"期间农场正常可玩（占用物除外）。
