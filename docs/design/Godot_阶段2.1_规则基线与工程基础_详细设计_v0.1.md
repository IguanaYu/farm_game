# 2.1 规则基线与工程基础：详细设计 v0.1

日期：2026-10-01。状态：设计提案，尚未实现。文档导航：[设计索引](第二大阶段详细设计索引.md)。本文中的“工程基础”指游戏信息、状态和一致性边界的设计，代码结构和实现任务另行编写。

## 1. 本阶段体验目标

玩家打开已有农场，看到洞窟入口和战备箱，能够理解自己要带什么、为什么这些物品会变成牌、失败会失去什么。新系统出现后，已有农场资产与操作仍可信。

本阶段先确定共用语言与状态，不要求现在就能完成整场探险。允许进入战备、查看一套演示装备和配组；尚不可用的出发入口明确显示“洞窟功能准备中”，不做会扣物的假出发。

## 2. 共用规则基线

| 设计项 | 本版本建议 | 设计目的 |
| --- | --- | --- |
| 人数 | 单人或双人 | 先做有意义且容易理解的合作 |
| 农场归属 | 各自农场、各自库存 | 朋友同局不合并家产 |
| 基础生命 | 每次正式出发 40／40 | 农场等待不成为恢复生命的门槛 |
| 战斗能量 | 每回合重置为 3 | 聚焦有限行动的选择 |
| 抽牌与手牌 | 每回合抽 5，手牌上限 10，回合末丢弃未保留牌 | 防止手牌无限积累 |
| 普通物品卡牌 | 占 N 格提供 N 个牌实例，不额外发永久基础牌 | 让装备与货物共同构成牌组 |
| 容器容量 | 胸挂 3×4、背包 4×4、保险箱 1×2 | 首版有布局空间，也有保护限制 |
| 可用时机 | 胸挂第 1、背包第 2、保险箱第 3 回合加入抽牌堆 | 让布局影响战斗启动 |
| 战斗间状态 | 生命持续；格挡、能量、手牌和临时状态重建 | 补给和休整有用途 |
| 操作入口 | 场景点击与面板，不新增实时移动要求 | 延续现有农场操作 |
| 保护规则 | 仅保险箱内白名单物品在失败时保留 | 风险可见而非全部保险 |
| 容器与配方 | 永久解锁，不计入死亡掉落 | 失败失去物品，不失去基本玩法入口 |
| 探险进行中 | 携带物品被本局占用；同一角色只参加一局 | 避免同一件物品被同时使用 |

数值集中作为设计初值，后续试玩可以改变。变化会影响战备、背包、战斗和经济，必须同步相关设计。

## 3. 功能 D2.1-01：农场新入口与主导航

洞窟入口放在农场边缘，外观与普通建筑可区分，不挡住原有地块、商店和仓库点击区域。战备箱位于入口附近；制作台可以先用带“尚未开放”说明的占位。

点击洞窟入口打开概览：最高到达层数、当前目标、单人出发、好友组队、战备配置、操作说明。第一次看到的是“建议先配好装备”；已经有活动局时，主按钮改为“继续探险”，显示单人／合作、层数、节点和原主机昵称。

战备箱直接打开个人配装，避免多次经过概览。关闭任何面板都回到同一农场视角。已有“今日集市”“仓库”等按钮位置不因新增入口产生误点；新增快捷入口安排在可展开的探险区。

### 入口的状态

| 当前状态 | 主按钮 | 可做什么 |
| --- | --- | --- |
| 无活动局 | 准备出发 | 整理装备、进入房间 |
| 房间内未出发 | 返回房间 | 改配装、准备、退出房间 |
| 单人局暂停 | 继续探险 | 恢复或查看放弃损失 |
| 合作局暂停 | 恢复原队伍 | 联系原主机、等待成员 |
| 结果等待入档 | 完成结算 | 重试保存、查看结果，不开新局 |
| 新功能未开发 | 查看设计中的功能 | 只预览，不消耗资产 |

## 4. 功能 D2.1-02：信息对象与归属

玩家可理解的对象包括农场资产、物品、物品生成的牌、配装方案、探险局、奖励、永久解锁和结算。每件装备是具体的一件物品；两把同名剑可以品质相同，但仍分别属于不同位置。

物品详情至少展示名称、类别、品质、占格、可放容器、全部来源牌、售价值、制作用途、是否受保护、目前归属。稀有种子额外显示现有种子词条和生长信息。装备品质与种子品质不直接相互换算。

归属只有一个：农场仓库、当前战备、活动局个人容器、当前节点公共区、待领取区、已消耗或已损失。同一物品从仓库装入战备时是移动，不是复制；配装预设只是要求清单，不拥有第二份物品。

“价值”分成四项：可出售金币、战斗用途、制作用途、收藏／任务用途。界面不给一个笼统总分替玩家决定。物品显示的出售价值不自动变成钱包金币，只有实际出售才记账。

## 5. 功能 D2.1-03：战备首页

推荐布局：左边仓库与筛选，中间三个容器，右边物品详情和牌组预览，下方配装预设、自动整理、清空配置、返回、单人／合作入口。

顶部显示生命上限、使用格数、首回合牌数、后续加入牌数、携带可售价值和失败保护价值。基础装备不能出售，因此价值显示“基础装备，不计可售价值”，不是标一个容易套利的价格。

选物品时显示放入哪个容器合法，并预览变化，例如“放入背包：第 2 回合加入 3 张牌；保护物品数不变”。点击“查看牌组”按加入回合分组，显示实际张数，重复牌叠成卡片但可展开。

暂时未实现拾取和战斗时，可以使用标有“演示”的样例物品；演示状态不写入正式库存，不允许出售或与真实物品混装。

## 6. 功能 D2.1-04：准备检查与规则提示

正式出发前至少检查：无未解决活动局、所有物品归属合法、布局无重叠、首回合有攻击牌、有可重复使用的防御手段、可恢复保存状态正常。前两项与非法布局属于硬性阻止；缺乏攻击／防御原型中以推荐与一次确认提示处理，避免强迫唯一配装。

若首回合牌库为空，必须阻止出发并提供“把装备放进胸挂”的解释，因为不能假定背包牌第二回合会救场。空容器不额外送隐藏牌。

出发确认展示实际带入物品列表、保护列表以及“死亡或主动放弃时未保护携带物品会失去”。第一次出发要求明确确认；以后仍保留可展开的清单和简短提示，不每次堆长篇说明。

## 7. 功能 D2.1-05：基础装备与失败后的底线

建议基础套装为旧短刀（1×2，提供两张攻击牌）、木盾（2×2，提供四张防御牌）、行囊工具（1×2，提供两张辅助牌），合计 8 格／8 张牌。具体牌见 2.2。

初次解锁探险时赠送一套。死亡后如果缺基础套装中的部件，可“补领缺失基础装备”；每种基础部件只允许拥有一件，活动局中的也计入拥有。补领不赠金币、不带品质提升。

基础装备不能出售、回收换材料、分享或作为制作输入，可以用来出发并在失败时损失。这样任何时候都能再玩，且不能通过丢弃和补领刷经济资源。

容器永久存在、容量升级永久保留；失去背包内物品不会让玩家失去背包本身。

## 8. 功能 D2.1-06：生命周期与农场并行

一局的逻辑状态为“准备 → 出发确认 → 探索／战斗／搜刮 → 撤离或失败 → 结果待保存 → 已回家”。暂停是保留当前状态的外层状态，不是撤离奖励来源。

活动局暂停时可返回农场种植、照料和处理未带入资产；被本局占用的装备、材料和种子标为“正在探险”，不可卖、做配方或配置另一局。不能通过复制配装解除占用。

农场现实时间继续前进，不随洞窟战斗回合快进。进入农场时补结算已经到期的种植、育种机和每日市场。农场货物与洞窟物品不自动合并成一个未经设计的库存区。

## 9. 场景示例

老玩家已有金币、词条种子和十块地。更新后农场保持原样，探险入口首次显示介绍。玩家领取基础装备，在胸挂放下短刀、木盾与工具，看到首回合 8 张牌、可售价值 0；保险箱为空。尚未开放战斗时只能预览，不会扣装备。

战斗功能开放后，玩家把木盾挪到背包，界面立刻显示首回合只有刀和工具的 4 张牌，并提示“防御牌从第 2 回合加入”。玩家可以理解这个选择的代价，而不是只看到攻击力没变。

## 10. 设计验证与待观察项

通过条件：玩家能找到新入口，解释三个容器、物品牌和失败保护；旧档资产没有被新系统重置；基础装备能避免破产等待，但不能带来套利。

重点观察：三容器是否过于复杂；首回合牌数是否应设置最低推荐值；演示内容是否容易被当成真实奖励。若复杂，先改善说明和预览，不直接新增更多系统。

本阶段交给后续代码计划的设计成果是状态表、战备页面信息、归属规则和共享初值。具体保存格式、脚本结构、联网协议不在本文决定。
