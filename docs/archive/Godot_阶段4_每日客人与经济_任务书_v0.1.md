# 小小农场 · 阶段 4 任务书：每日客人、交易与经济升级（v0.1）

编写日期：2026-09-29。适用工程：Godot 4.6.1，Windows，项目根目录 `E:\gpt\godot\farm`。本文自包含：接手本阶段的开发者只需本文、仓库代码和两份规则文档即可开工。

## 项目速览

点击式种田游戏，玩家不控制小人移动，直接点击地块和建筑操作。单人首版核心循环：**选种 → 播种与照料 → 现实时间成熟（离线也生长）→ 收获作物和新种子 → 育种或复制 → 比较报价出售 → 购买、扩地与升级 → 下一轮**。多人玩法不在首版范围内。

单人首版共 6 个阶段：1 最小闭环 → 2 种植照料与成长 → 3 育种仓库育种机 → **4 每日客人与经济（本任务书）** → 5 体验与素材 → 6 回归与交付。

## 通用开发约定（对所有阶段生效）

1. **一次只接一个阶段。**先读材料、读代码、读测试，再列出本阶段具体改动清单；通过本阶段全部验收后才算完成。跨阶段的最小依赖改动记录在交付报告里。
2. **规则层负责裁定。**客人抽取、公式与系数、报价、拆批结算、折扣取整、扩地与升级判断全部放在 `scripts/domain/` 或 `scripts/services/`；界面只发起操作并展示结果。存档只存数据，不存场景节点。
3. **保护旧档。**本阶段把 `FarmGame.SAVE_VERSION` 升为 4，保留原文件路径并做 3→4 迁移；阶段 3 存档样例必须能升级读入。**扩地后六地旧档读取仍为六块已拥有地，不自动赠送扩地**。存档写入失败给玩家可见提示。
4. **随机与离线结果可复现。**每日客人与公式的抽取以"北京时间日期"为键保存当天结果；同一天内反复读档不重抽；离线跨多日只显示当前日，不补出过去客人。测试用受控时间与固定随机种子，不修改系统时钟。
5. **每项功能同时有可玩入口和可核对结果。**新增场景节点用明确名称和路径，避免靠无筛选的 `get_children()` 猜节点身份。素材原件在 `art/lowpoly/`，运行时副本在 `assets/`，映射见 `assets/stage1_manifest.json`。
6. **交付报告**写明：修改文件、实现的规则、未定规则所用的可调初值、自动测试命令及结果、手动试玩步骤及结果、旧档迁移结果、未解决问题。验收失败项如实标记。

## 开发内容

### 1. 每日客人系统

- **六位客人**各有固定植物偏好：三位长期喜欢 20 分钟植物，三位长期喜欢 2 小时植物；身份与偏好固定（名字与形象可用占位，正式素材阶段 5）。
- 每天按**北京时间零点**刷新：从六位中抽三位出现，并为**两种植物**各抽当天的属性收购公式与系数。
- 只保留当天状态；离线跨数日回来只看到**当前日期**的三位客人及报价，不补卖、不累计。
- 商店 2 级：可**锁定一位客人**，使其每天持续出现，直至主动更换；**另外两位仍随机**。锁人不锁其每日属性要求。更换在下一个北京时间零点生效，旧锁在此之前有效。
- 商店 3 级：可**锁定已锁客人的某一种植物当天出现的公式类型**（只能锁当天实际出现的类型，不能凭空选择）。锁的是"单属性/主辅属性及其关注的属性"，**不锁系数**；系数每天仍从对应池重抽。公式锁持续到主动更换，更换在下一个零点生效。三级商店不增加新的客人锁位。

**北京时间零点实现建议**（可用等价方案，需报告说明）：北京时间为 UTC+8 固定偏移、无夏令时。`day_index = floor((unix_utc + 8*3600) / 86400)`；存档保存 `day_index` 与当日抽取结果，读档/跨日时对比后决定是否重抽。参考 [Godot Time API](https://docs.godotengine.org/en/4.x/classes/class_time.html)。

### 2. 收购公式与报价

- 公式只给**正向**属性加成，作用于作物的三项属性（含水量、纤维含量、色泽，来自批次数据）：

| 公式类型 | 形式 | 系数池 |
| --- | --- | --- |
| 单属性 | `1 + 主属性 × 系数` | 0.08 / 0.10 / 0.16 |
| 主辅属性 | `1 + 主属性 × 主系数 + 辅属性 × 辅系数` | 主 0.06 / 0.08 / 0.10；辅 0.02 / 0.04 / 0.06 |

- 关注的属性、公式类型和系数按日刷新；客人收购其固定偏好的植物时，公式倍率**再乘 1.2**。
- **结算结构**：`出售计价额 = (植物基准分 + 各项加分) × 最终售卖倍率`；`本次出售所得金币 = ⌊所售作物计价额合计 ÷ 100⌋`。先合计整笔出售的全部计价额再统一取整，不逐个作物取整；金币只显示整数。
- **默认出售始终可用**：`(基准分 + 加分) × 1.2`，作为低报价兜底，不强迫卖给客人。
- **金克拉肥料**：批次带金克拉效果时，最终倍率**加 0.2**（默认 1.2 → 1.4；客人公式倍率 ×1.2 偏好后同样 +0.2）。
- 等级加分、波动按植物基准分计算，与浇水、施肥、遭遇加分**相加后**再乘倍率（沿用阶段 2 批次构成）。
- 调试目标：玩家种地与该植物都 2 级、遇到合适客人时，最终报价倍率约 1.5 倍。

### 3. 拆批出售与交易安全

- 每批 5 个作物可**按数量拆开**卖给不同客人（例如 2 个 + 3 个），或选择默认出售。
- **出售扣库存与加金币必须是一次原子操作**：不能卖了作物没拿到金币，也不能重复点击获利。购买同理。
- 报价面板展示每个客人对当前选中批次的单价与总价，及数值来源（基准分、各项加分、公式、倍率）。

### 4. 商店统一交易：批量、折扣、回收

- 商店商品支持**批量购买**：种子（两种基础种子，不限量）、四种肥料、各类升级。
- **等级折扣**：商店每升一级，店内所有商品购买价优惠 5%（2 级 −5%，3 级 −10%，4 级 −15%）。**同一笔购买的商品标价合计后打折，最后四舍五入到整数金币**。例：2 级商店买 3 粒标价 10 金币的种子，30 → 28.5 → 支付 29 金币。
- **种子回收**：所有种子统一 **5 金币/粒**卖回商店，不按来源、种类、品质加价。

### 5. 扩地与升级接入

| 项目 | 价格（试算初值，均可调） |
| --- | --- |
| 第 7 / 8 块地 | 1,400 / 1,600 金币 |
| 第 9 / 10 块地 | 15,000 / 17,000 金币 |
| 购买商店 1→2 / 2→3 / 3→4 级 | 1,500 / 15,000 / 17,000 金币 |
| 仓库 1→2 / 2→3 / 3→4 级 | 1,200 / 15,000 / 17,000 金币 |
| 水壶升至 2 级 | 15,000 金币 |
| 育种机 1→2 级 | 17,000 金币（2→3 占位，报告标注） |

- 扩地只需金币，不设种地等级门槛；逐块购买。
- **结构重构**：当前 `FarmGame.PLOT_COUNT = 6` 及世界场景的六地循环需要改为"最多 10 块、按已拥有渲染与点击"，不能只在画面上添四块地。同步扩展地块数据、场景点击区域、存档校验和测试。
- **水壶 2 级**（阶段 2 已预留数据）：一次浇水覆盖 **3 块地**；每个有效浇水时段的加成从 +10% 提高到 **+20%**；同一时段多次有效浇水时**取最高加成**（好友高级水壶规则为多人版预留，单人版只需保证"取最高档"成立）。
- 接入育种机升级购买（阶段 3 已有机器逻辑）。
- 商店 2 级的锁客人、3 级的锁公式入口随本阶段客人系统一并接入。

### 6. 经济记录

- 保存一份**经济记录**（存档内或独立文件均可，报告说明）：每轮实际收入、种子与肥料成本、净收入，以及攒到主要升级所需的种植轮数。只记录，不调数值；阶段 6 再平衡。

## 验收步骤与通过条件

- 用受控时间测试北京时间 **23:59:59 与次日 00:00:00** 的交界：客人及报价只在跨日后变化；跳过多日只显示当前日。锁客人、锁公式及更换均在**次日零点**生效，系数仍逐日重抽。
- 同一批 5 个作物拆成 2 个和 3 个分别出售，再读档：数量恰好清零，金币恰好等于两次整笔结算之和；默认出售一直可选。
- 对以下三项各做一个**可手算样例**并写入交付报告：① 客人公式 × 植物偏好 1.2 + 金克拉 +0.2；② 整笔计价额合计后 ÷100 向下取整；③ 商店折扣后四舍五入（如 28.5 → 29）。
- 重复快速点击购买或出售按钮不产生额外收益、不重复扣库存。
- 扩到十块地后都能点击、播种、离线成熟和收获；升级、容量、商品解锁及金币扣减存读档一致；**六地旧档读取后仍为六块已拥有地**。
- 水壶 2 级覆盖三块地；同一时段混合浇水时取最高加成。
- 阶段 1～3 测试全部通过（含按十地结构更新后的阶段 1 测试）。
