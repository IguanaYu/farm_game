# 小小农场：第二大阶段实机测试清单 v0.1

编写日期：2026-10-01。依据：[2.9 交付报告 §5 未验证项](./archive/Godot_阶段2.9_交付报告.md)、[整体开发计划 §12/§14/§16](./Godot_第二大阶段_农场与合作洞窟_整体开发计划_v0.1.md)、各子阶段交付报告。

## 0. 定位与范围

自动化测试（d21~d29＋stage1~6＋world_picking，共 32 项）已在 headless 口径全部通过，规则数值、序列化、恢复矩阵不重复手测。本清单聚焦自动化**覆盖不到**的部分：

1. 两台物理设备的真双机合作（此前仅同进程双 peer 经 127.0.0.1）。
2. 真断网掉线/重连/主机恢复演练（此前为代码内故障注入）。
3. 导出包 `build/Farm.exe` 的实机表现与分辨率适配。
4. 真人试玩观察（试玩关口 A/B、平衡初值、单局时长）。

优先级定义：**P0**＝数据丢失/复制、崩溃、流程卡死；**P1**＝功能不符或体验明显差；**P2**＝观察记录项，不判失败。

## 1. 环境与准备

| 项 | 说明 |
| --- | --- |
| 设备 A（主机） | Windows，运行 `build/Farm.exe`（或 Godot 4.6.1 打开工程按 F5） |
| 设备 B（客机） | 另一台 Windows 机器，同一版本。首轮流必须真双机；后续用例可退化为同机双实例 |
| 网络 | 同一局域网。联机端口 **UDP 31967**：导出包首次创建房间若弹出防火墙授权，选择"允许"；若未弹窗且客机连不上，在防火墙手动放行 |
| 存档位置 | `user://`（Windows 下 `%APPDATA%\Godot\app_userdata\小小农场\`）。涉及存档的用例**先整目录备份** |
| 旧档样本 | 迁移测试需一份内容版本 v5 的存档（第一大阶段版本生成）。可用旧档备份，或在 git 历史版本导出包里新开一档玩几步生成 |
| 调试键 | F9（全部立即成熟）仅开发构建有效，导出包无效——导出包验证种植时不要依赖它 |
| 时钟 | 涉及每日客人/离线成长的用例，注意设备时钟可被人为修改会影响结算（已知限制，不是缺陷） |

## 2. 用例清单

### T0 自动化回归基线（每次实机测试前跑一遍）

- [ ] T0-1（P0）编辑器 headless 全量 32 项通过，结果与 `tests/d29_full_regression_output.txt` 一致。命令见 [README §验证](../README.md)。

### T1 农场回归——第一大阶段未被新内容破坏（设备 A，编辑器或导出包）

- [ ] T1-1（P1）旧档正常进入：种植→照料（浇水/施肥各一次）→收获→仓库看到新种子。
- [ ] T1-2（P1）集市：出售一批作物、锁定一位客人、次日（可改系统时间模拟）客人刷新。
- [ ] T1-3（P2）育种机照常复制；扩地/水壶等升级入口正常。
- [ ] T1-4（P1）农场场景里新增的洞窟入口、战备箱、制作台建筑可点击打开，不影响原有地块/建筑点击。

### T2 战备与出发（单人，设备 A）

- [ ] T2-1（P1）战备界面：装/卸武器护甲、在胸挂/背包/保险箱间移动物品、旋转、自动整理、拆分堆叠，各操作后牌组预览（首回合可用牌/后续加入牌/总牌数）正确刷新。
- [ ] T2-2（P1）三容器分层提示可理解：胸挂第 1 回合、背包第 2 回合、保险箱第 3 回合加入牌库（实际回合数以战斗内观察为准，见 T3-2）。
- [ ] T2-3（P0）免费基础装备：失败后可再领一套，且**不能出售换钱**（套利已被 d29 断言，实机复核领两次不出异常）。
- [ ] T2-4（P1）出发检查：携带价值、死亡可能损失、保护区提示显示；未准备/物品被占用时有原因提示。
- [ ] T2-5（P2）保存一套配装→清空→按配置补齐，只补已有物品，不自动花钱。

### T3 单人洞窟完整循环（设备 A）

- [ ] T3-1（P0）一层苔石浅洞：地图分支可见、只能进相邻未完成节点、旧节点不可重复拿奖励；战斗/宝箱/事件/休整各进至少一次。
- [ ] T3-2（P0）战斗：3 能量抽 5 牌、出牌/防御/消耗品生效、敌人意图可见；胸挂/背包/保险箱的牌按第 1/2/3 回合加入（对照 T2-2）。
- [ ] T3-3（P1）搜刮：拾取前能看到尺寸、产生卡牌、价值预览；背包放不下时有移动/丢弃/放弃选择，界面不自动丢旧装备；离开节点提示未领物资将放弃。
- [ ] T3-4（P0）中途撤离：在撤离点确认后正常结算回家，收益入账（参考初值：一层打到第 4 排撤离期望可售 ≈59 金币，明显偏离时记录）。
- [ ] T3-5（P0）完整两层：进入二层铁根矿窟、击败首领、带回奖励；结算界面列出带入/带回/消耗/损失/保护/金币变化/目标进度。
- [ ] T3-6（P0）死亡：携带品损失、保险箱白名单物品保留；回家后基础装备可再领（连 T2-3）。
- [ ] T3-7（P0）回家不重复发放：出发装备返回后不另发一份；再次打开结算界面或重启游戏不能重复领取；仓库满时撤离仍成功、产物进待领取区。
- [ ] T3-8（P1）回家成长闭环：制作台至少一个配方可用、岩芽菜可种、目标看板进度更新——形成"再玩一轮"的理由。

### T4 存档迁移与单人异常（设备 A）

- [ ] T4-1（P0）v5 旧档载入：提示迁移、进档后原有作物/金币/仓库完整、内容版本变为 v7；迁移前存档有备份。
- [ ] T4-2（P0）局中强退：洞窟内直接杀进程→重启，恢复同一地图与奖励（d24 已模拟，实机复核一次）。
- [ ] T4-3（P1）存档写入失败提示：把 `user://` 设为只读后游玩触发保存，应提示而非静默丢失；恢复可写后备份恢复可用。

### T5 真双机合作（设备 A 主机 ＋ 设备 B 客机）——本清单核心

- [ ] T5-1（P0）建房加入：A 创建房间→B 输入 A 的局域网 IP 加入；满员第 3 人被拒；版本不一致被拒并提示。
- [ ] T5-2（P1）准备与出发：双方准备后主机发起；B 未准备时出发被阻止并说明原因。
- [ ] T5-3（P0）共同选路：地图投票，双端看到相同地图/节点/敌人；分歧时停留在选择界面，"推荐路线/需要补给/建议撤离"快捷信号可发出并被对方看到。
- [ ] T5-4（P0）合作战斗：双人共同回合各自出牌（含快捷信号"我来挡/先集火/我能救你"）；同时出牌按裁定顺序生效不冲突；敌人生命为双人缩放口径。
- [ ] T5-5（P0）倒地与救援：一名玩家倒地→不能出牌、不计入回合结束；队友救援牌恢复到 8、每人每场一次；全部倒地立即失败；胜利时倒地者恢复 4。
- [ ] T5-6（P0）搜刮与分享：公共物资领取双端记录一致；分享三步（提出→确认/取消）中取消不丢物；A 不能操作 B 的物品/牌。
- [ ] T5-7（P0）共同撤离双确认：一端确认后等待另一端；全员确认→冻结操作→结算。**结算分别落回各自农场档**：双端各自金币/物品正确，主机不代写客机农场档。
- [ ] T5-8（P1）个人放弃：一成员中途放弃（结算本人、会话保留），另一成员可继续至撤离。
- [ ] T5-9（P2）记录每局等待时间（对方操作时自己的空闲）、路线分歧次数、公共物资分配体验——试玩关口 B 数据。

### T6 真断网与主机恢复演练（在 T5 流程中途执行）

- [ ] T6-1（P0）客机掉线：战斗或选路中直接断开 B 的网络（禁用网卡/关 WiFi）→ 主机在约 2.5s 内标记离线并**暂停一切裁定**（不判撤离不判失败），界面有等待提示。
- [ ] T6-2（P0）客机重连：B 恢复网络后重连→接回原成员位，回合/手牌/阶段与掉线前一致；期间主机补发的未决结算不重复入账。
- [ ] T6-3（P0）主机崩溃恢复：杀掉主机进程→A 重启并载入局档→B 用原身份重连→局 ID 不变、进度延续。
- [ ] T6-4（P1）等待上限体验：B 长时间不回，观察 A 端提示是否足够（120s 上限 UI 提示为已知薄弱项，记录表现）。
- [ ] T6-5（P2）互联网直连：两地不同网络尝试直连（需公网 IP/端口映射），仅记录可行性结论——按总计划 §9.1，互联网方式未选定前联机交付保持"未完成"标记。

### T7 导出包与显示（build/Farm.exe）

- [ ] T7-1（P0）导出包冷启动无报错：双击启动，主场景正常渲染，进入农场/洞窟各一轮；F9 无效（预期行为）。
- [ ] T7-2（P1）分辨率：1920×1080 全屏与窗口化各跑一次主流程；再拖成小窗口，检查 HUD/战备/结算面板无遮挡错位（已知未验证项）。
- [ ] T7-3（P1）双人满包实机：合作局中双方背包全满状态下开结算，检查帧率与面板布局。
- [ ] T7-4（P2）图标正确显示（任务栏/窗口）；正式美术与音效**无素材**，只记录占位观感，不判失败。

## 5. 首轮实机测试缺陷记录（2026-10-02，Windows 11 / 2560×1440 @175% 缩放 / 双显示器）

| 编号 | 优先级 | 现象与根因 | 修复 | 验证 |
| --- | --- | --- | --- | --- |
| D-1 | P0 | **战斗界面所有按钮实机点击无响应**（选择遭遇/出牌/结束行动全死）。根因：`battle_screen._build` 末尾的终局层容器 `overlay_center` 常驻全屏、树序在最上、未设 `mouse_filter`，拦截了底下全部鼠标输入。自动化测试均为 headless 直驱规则层，从未模拟 UI 点击，故 2.3 起未暴露。 | `overlay_center.mouse_filter = MOUSE_FILTER_IGNORE` | 实机复核：战备/出发/进入战斗链路恢复（用户实测进入战斗第 1 回合） |
| D-2 | P1 | **全游戏 9 个面板按钮文字浅白配浅底看不清**。根因：各面板 `_button(text, fill, border)` 辅助均未设 `font_color`（Godot 默认浅白 #e0e0e5）。 | 8 个面板统一加 `#35513d` 深色字（farm_hud 的 _plain/_solid_button 原本就有字色） | 已生效（用户截图确认按钮文字可读） |
| D-3 | P1 | **手牌卡牌与战备箱仓库列表行文字看不清**。同类：卡牌 Button（米色底）与仓库行 DragButton（浅黄底）无 font_color。 | 两处加 `#35513d` 深色字 | 已修，待用户复测 |
| D-4 | P1 | **高分屏文字小且模糊**。根因：项目未开 `allow_hidpi`，175% 缩放下按 96 DPI 渲染再被系统拉伸；且窗口实际仅 745×494 物理像素，1440×900 画布被缩 0.52 倍。 | `allow_hidpi=true` + 渲染器 gl_compatibility→mobile(Vulkan) + `snap_fonts_to_pixels=true`；建议玩家最大化窗口 | 用户截图确认文字清晰 |
| D-5 | P2 | **战斗在无玩家操作时"第 0 回合满血自动胜利"**（按钮失灵期间的局产生）。规则层为何自动判胜待查，可能与浅层遭遇/空牌组自动结算有关。 | 未修，待查 | — |
