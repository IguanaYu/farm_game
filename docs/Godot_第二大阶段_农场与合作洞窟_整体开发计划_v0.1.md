## 1. 总目标与本阶段完成的样子

把现有农场扩展为一款可以单人游玩、也可以与好友合作的洞窟探险游戏。农场提供稳定资源和备战能力，洞窟提供主要主动游玩内容、稀有资源和成长目标。

本阶段结束时，玩家应当能够：

1. 在自己的农场种植、育种、出售作物，用所得准备装备和补给。
2. 打开战备界面，把武器、护甲、补给放入胸挂、背包或保险箱，预览它们产生的卡牌。
3. 选择单人出发，或与一名好友组队进入同一场洞窟探险。
4. 在分支地图上选择战斗、宝箱、事件、休整和撤离等节点。
5. 用各自的卡牌共同战斗，查看敌人意图，并通过攻击、防御、支援和道具使用形成配合。
6. 搜刮个人奖励和公共物资，整理空间、分享物品，判断战利品是否值得拖累牌组或承担继续深入的风险。
7. 在撤离点选择带着收获回家，或继续进入更深区域；死亡按规则损失未保护物品。
8. 回家后出售货物、种植新种子、制作装备或升级设施，再次出发。
9. 保存和恢复进度；联机断线、重连及重复结算不会造成物品复制或旧档损失。

**阶段的核心体验是：我搜到了想要的东西，它也改变了我的战斗能力；我现在撤离，还是继续深入？**

## 2. 已确定方向、原型规则与边界

### 2.1 作为本计划依据的方向

- 主循环为“农场备战 → 下洞 → 战斗与搜刮 → 撤离 → 回家成长”。
- 多人为纯 PvE 合作，各人使用自己的牌，队伍走同一条路线、面对同一组敌人。
- 物品有带回家后的用途，也会对应战斗卡牌；市场价值与战斗价值分别设计。
- 搜刮会影响背包和牌组，撤离是重要决策，不要求每次打到底。
- 农场原有现实时间成长、每日客人、育种和本地存档继续保留。

### 2.2 本计划采用的原型基线

以下是为了使开发可以落地而提出的初值，**不代表已确认的最终玩法**。第一次实现时集中配置，并在交付报告中记录实际采用值和修改原因。

| 项目 | 原型基线 | 需要观察什么 |
| --- | --- | --- |
| 合作人数 | 首先验收 1～2 人，数据结构保留扩展能力 | 两个人是否已经有明确配合和分配选择 |
| 洞窟规模 | 先完成一层闭环，再扩到两层；四层留作后续内容扩展 | 两层是否足以产生深入与撤离的选择 |
| 单局长度 | 两层目标约 20～35 分钟，可提前撤离 | 等待、战斗与整理是否拖长一局 |
| 基础战斗 | 每回合 3 点能量、抽 5 张牌 | 出牌选择是否充分，货物牌是否过度卡手 |
| 玩家行动 | 队伍共享玩家回合，各人可提交出牌，按裁定顺序生效 | 自由出牌是否混乱，是否需要更强提示 |
| 物品占格与卡牌 | 占用 N 格的普通物品提供 N 个卡牌实例，可有相同牌 | 大体积物品是否产生合理代价 |
| 胸挂、背包、保险箱 | 分别在第 1、2、3 回合加入本场战斗牌库 | 延后可用是否好理解、有选择价值 |
| 死亡保护 | 保险箱内允许保护的物品保留，其余携带物品损失 | 新手损失是否过重，保险箱是否消除了风险 |
| 撤离方式 | 全队共同撤离；有人选择深入时留在决策界面协商 | 是否需要未来加入个人撤离 |
| 联机结构 | 主机裁定洞窟局，各人持有自己的农场档 | 同步、恢复与跨端结算能否稳定完成 |
| 胜利条件 | 击败第二层首领后可带回奖励，也可中途撤离 | 首领目标和搜资源目标是否都成立 |

### 2.3 本阶段范围

**必须交付：**单人和双人洞窟、物品生成卡牌、战斗、分支选路、搜刮、物品分享、撤离与死亡、带回农场、基本制作与成长、旧档迁移、断线恢复、Windows 导出。

**后续再扩：**三至四人、四层完整内容、好友农场访问与协作种地、自由家园装修、长期剧情、更多职业和装备流派。

**本阶段不安排：**PvP、偷菜、跨玩家拍卖行、陌生人自动匹配、公会、开放世界实时移动战斗、移动端移植。好友联机的联网方式要在技术验证时确定，不能把“局域网能连”写成“互联网好友可直接玩”。

## 3. 玩家从农场出发到回家的完整流程

### 3.1 农场准备

农场内增加洞窟入口、战备箱和制作台入口，沿用点击场景建筑打开面板的方式。玩家无需为了进入洞窟增加角色移动操作。

战备界面显示当前生命、携带空间、装备、补给、保护物品，以及这套物品生成的牌组。玩家可查看“首回合可用牌”“后续加入牌”“总牌数”和攻击、防御、支援的大致构成。提示应解释物品如何影响战斗，不只展示装备分数。

准备操作包括装备、卸下、移动容器、旋转物品、自动整理、拆分可堆叠数量、补充消耗品、保存一套配置和按配置补齐已有物品。自动补齐不会未经明确操作自动花钱购买缺失物品。

出发前显示本次携带价值、死亡可能损失的物品和保护区。提供一套低成本基础装备，使玩家遭遇失败后仍能再次出发；发放条件和数量集中配置，防止反复领取后出售套利。

单人点击出发；合作先进入房间，所有人准备完成后由主机发起。未准备、版本不同、存档写入失败或物品被占用时，说明原因并阻止进入。

### 3.2 洞窟探索

地图显示当前位置、可选相邻节点、已访问路线、层数以及下一撤离机会。已揭示节点类型可见，具体宝物保持未知；奖励提示给出类别和风险，不提前透露全部随机结果。

一次只进入一个节点。战斗结束后先处理搜刮和整理，再返回地图；事件选择完成后写入本局结果。点击旧节点、隔层节点或已完成节点不能重复获取奖励。

队伍在地图上标记或投票，所有在线且仍参与本局的成员确认同一选择后进入。分歧保留在选择界面，提供“推荐路线”“需要补给”“建议撤离”等快捷表达。

### 3.3 搜刮、深入与撤离

玩家看到个人奖励和公共物资，并能预览尺寸、产生的卡牌、价值和回家用途。拾取前提示会增加多少牌、何时可用、是否占用保护区。

没有空间时可以移动、丢弃、分享或放弃拾取，界面不自动丢弃旧装备。离开当前节点会明确提示未领取物资将放弃；公共物品的领取和分享记录可回看。

撤离点显示各人的生命、携带价值、保护价值、剩余补给以及更深层可能出现的资源。共同确认撤离后冻结本局操作，生成结算，再回各自农场。

### 3.4 回家处理

结算界面显示带入物品、实际带回物品、消耗品、损失、保护物品、金币变化、任务进度和新解锁。出发装备原本就属于玩家，返回时不能再次发一份。

回家后新增物品进入装备／材料仓库或待领取区，稀有种子进入原有种子体系。仓库满也能完成撤离，产物留在待领取区；再次打开结算或重启不能重复领取。

## 4. 功能设计：物品、空间与卡牌

### 4.1 物品分类

| 类别 | 战斗中的作用 | 回家用途 |
| --- | --- | --- |
| 武器 | 提供攻击、破甲或控制类牌 | 留用、出售、用于后续制作 |
| 护甲／防具 | 提供格挡、减伤或保护队友牌 | 提高出发能力 |
| 工具／饰品 | 提供抽牌、能量、侦察或特殊条件牌 | 支撑不同配装 |
| 补给 | 恢复、解状态、临时强化；使用后消耗物品 | 农场制作或购买补充 |
| 矿石／材料 | 提供弱牌、条件牌或负担牌 | 制作、设施升级或出售 |
| 稀有种子 | 提供与植物特色有关的牌或负担 | 回家种植、继续育种 |
| 贵重货物 | 高出售价值，可有较弱或带代价的牌 | 兑换金币与成长资源 |

每件物品包含定义 ID、实例 ID、尺寸、容器位置、品质、来源、基础价值、对应牌列表和保护资格。金币记账与实物分开，避免一份价值既当金币又当货物重复结算。

第一版装备优先使用固定品质与少量差异，不同时引入复杂随机词条、耐久、维修和装备强化。现有种子的词条与品质独立保留。

### 4.2 格子背包

- 胸挂、背包、保险箱具有独立二维格子，容器容量可由后续升级改变。
- 支持拖放与点击放置两种操作；可旋转物品；越界、重叠、非法容器给出提示并回退。
- 普通物品按照实际占格数提供卡牌实例；原型内容先使用矩形，复杂拼图形状以后扩展。
- 自动整理必须保留容器归属和保险箱保护选择，不悄悄把物品挪到别的容器。
- 为防止材料堆叠规避牌组代价，原型中洞窟携带物品不堆叠；回家材料仓库允许按定义堆叠。以后开放携带堆叠时需重新规定占格、卡牌和价值计算。
- 保险箱只允许配置表标记的物品；暂定稀有种子和小型材料可放，大型武器与大货物不可放。具体名单为试玩初值。
- 非战斗节点可以整理、分享和丢弃；战斗中锁定背包布局，避免即时改变已经生成的牌库。

### 4.3 物品生成牌组

牌实例记录来源物品实例和序号。例如占 3 格的铁剑可以提供“挥砍、挥砍、重击”，不是必须三张不同牌；占 2 格的矿石可以提供两张“笨重货物”。界面可从牌反查对应物品，也可从物品查看所有牌。

新战斗开始时，根据当前布局重新构建牌库。胸挂物品牌在首回合参与抽牌；背包物品牌在第二回合洗入；保险箱物品牌在第三回合洗入。延后加入只代表进入抽牌堆，不保证当回合抽到。每件物品每场战斗只加入一次。

战斗途中不会把新战利品立即塞进手牌；战斗结束拾取后，从下一场战斗开始生效。更换容器改变下一场战斗的加入时机。

普通装备牌打出后进入弃牌堆，抽牌堆空时洗入弃牌；消耗／移除牌按定义处理。负担牌可以是低收益牌、占用手牌或需要花能量处理的牌，首版避免大量强制扣血，使玩家能看懂携带代价。

消耗品的各张牌引用同一剩余使用次数。一份药水有多张来源牌时，使用一张后不能再通过另一张重复使用；当物品耗尽，该物品剩余手牌、抽牌和弃牌中的关联牌全部失效或移除。结算准确扣除实体物品。

## 5. 功能设计：卡牌战斗与合作

### 5.1 战斗信息与基本操作

战斗界面包括敌人生命、意图和状态，各玩家生命、格挡、能量、手牌数量、准备状态，以及个人手牌、抽牌／弃牌查看入口和战斗日志。

卡牌至少包含名称、费用、目标类型、效果和来源物品。鼠标悬停或点击详情可解释状态；选牌后高亮合法目标，显示预计效果。无效目标或能量不足只给原因，不扣资源。

支持点击牌再点击目标，也可拖牌到目标；取消选择不改变状态。出牌结果以规则层裁定为准，动画只展示结果；动画队列不得造成第二次伤害。

### 5.2 回合与效果

推荐初始流程为：回合开始 → 加入本回合到期的物品牌 → 补充能量与抽牌 → 玩家出牌 → 全员结束行动 → 敌人行动 → 状态结算 → 下一回合。

开发时明确格挡清除时点、持续伤害触发时点、抽牌堆为空时的处理、击杀后剩余效果、范围攻击结算顺序和胜负同时发生的裁定。所有效果采用一套执行顺序，并给出固定输入算例。

第一批效果包括单体攻击、格挡、治疗、抽牌、临时能量、破甲／易伤和持续伤害；合作加入为队友格挡或恢复的牌。多回合状态显示剩余回合，效果和移除时点可查。

敌人预先显示下一步行动类型和目标；玩家可以据此选择挡伤、控制、集火或恢复。状态改变使伤害数值变化时，更新预览；已承诺的意图不因玩家反复开界面重抽。

### 5.3 双人合作规则

- 每个人有自己的生命、能量、手牌、抽牌堆和装备；敌人和路线是共享的。
- 玩家回合允许两人自由提交出牌请求，主机按收到并验证后的动作序列依次执行，广播结果。
- 两人同时攻击同一目标，后执行的请求如果目标已经死亡则拒绝并退回待选状态，不扣能量或牌。
- “结束行动”允许在敌人回合尚未开始前取消；只有全体仍能行动的玩家都结束，才进入敌人回合。
- 防御、治疗队友等效果受合法目标限制，不能操作或消耗队友的牌和装备。
- 敌人数量、生命或攻击按人数配置，先避免简单把全部数值翻倍；单人与双人都需要独立试玩。
- 提供集火标记、求保护、准备结束等快捷信号；首版不另做语音系统。

### 5.4 倒地、失败与复活

原型采用“生命归零先倒地，不能出牌；队友可通过有限的救援资源救起；所有人倒地则失败”。救援次数、恢复生命、是否产生负担均为配置初值。

倒地玩家可看队友战斗和日志。战斗胜利后，倒地玩家以低生命恢复，随队继续或撤离；首次原型不让某一名玩家永久死亡后长期只能旁观。

失败统一生成死亡结算：扣除未保护的带入装备和本局战利品，保留保险箱允许保护的物品及农场内未带入资产。退出游戏、断线与主动放弃不等同于正常撤离，具体按第 9 节恢复规则处理。

## 6. 功能设计：洞窟地图、节点与战利品

### 6.1 分支地图与深度

一层由有限节点和有向连接构成，确保起点能到达撤离或层末目标；不可生成没有出口的必经死路。第一层约 6～8 个实际经过节点作为初值，支路提供不同风险和资源倾向。

第二层出现更有价值的材料、种子与装备，也提高战斗压力。第一层与第二层均有撤离机会，最终首领奖励不应压低普通提前撤离的价值。

地图在出发时使用本局随机种子生成并保存，节点奖励在首次裁定时生成后固定。恢复同一局不重新生成地图、敌人或宝箱。

### 6.2 节点类型

| 节点 | 主要功能 | 决策与反馈 |
| --- | --- | --- |
| 普通战斗 | 击败一组敌人、搜刮基础物资 | 是否消耗补给换取收益 |
| 精英战斗 | 明显更危险，提供高价值候选奖励 | 提前展示风险级别与资源倾向 |
| 宝箱／采集 | 获取材料、种子或货物 | 空间有限时选择带走什么 |
| 事件 | 付出物品、生命或金币换结果 | 选择前说明确定代价与可能结果类别 |
| 休整 | 恢复或获得短期准备效果 | 恢复与获取额外收益之间取舍 |
| 撤离 | 确认带回当前物品 | 展示现有收获、损失风险和深入收益 |
| 层末／首领 | 通往下一层或完成本次探险 | 确认准备、提供成长目标 |

原型先做固定地图节点列表；分支生成在闭环跑通后加入。事件与奖励都通过定义表配置，不把文案里的概率和规则写成两份。

### 6.3 搜刮与分配

战斗奖励分为个人奖励和公共物资。个人奖励最初归各玩家，允许主动分享；公共物资每件只能被一人取得。

领取公共物品由主机校验物品仍存在、玩家可操作、空间合法，再原子转移归属。两人同时点同一物品只有一人成功，另一人看到“已被领取”和新的公共库存。

分享使用“提出物品 → 对方确认并选择位置 → 主机转移”流程；取消、对方满包或断线时物品留在原主人处。禁止出现双方都持有或双方都失去的中间状态。

丢弃物品进入当前节点公共区域，其他玩家可拾取；离开节点后不可回头刷取。释放空间会改变下一场的牌组，当前战斗不提供丢弃入口。

资源表分别控制层数、节点类别、品质和用途。必须出现贵但拖累战斗的货物、价值一般但救急的装备、贵且能打的稀有装备，避免所有物品都能用单一价值排名。

## 7. 功能设计：农场、制作与长期成长

### 7.1 农场与洞窟相互支持

原有作物可以出售，部分作物增加制作补给的用途；洞窟材料用来制作装备和升级战备设施；稀有种子解锁新植物并继续使用现有育种、照料和出售规则。

新增植物必须配齐基础生长配置、词条适用性、遭遇、经验、市场报价和模型／图标，不能只加入一个可以获得但无法播种的种子。

下洞过程中农场仍按现实时间成长；回家统一结算离线时间和每日市场。多人洞窟只同步本局，不把某人的农场实时交给其他人操作。

### 7.2 设施与仓库

- **战备箱：**管理装备、容器、配装预设和出发入口。
- **制作台：**展示配方、所需金币与材料、缺少项、可制作数量和成品详情。
- **装备／材料仓库：**与现有作物区、种子区区分，按武器、防具、补给、材料、货物筛选；支持排序、详情和快捷移入战备。
- **设施升级：**增加仓储、开放配方或扩充容器；升级预览显示明确效果。
- **成长看板：**显示已到达层数、已完成目标、已解锁资源和下一目标。

制作采用一次扣材料并生成成品的事务，连续点击和重启不重复制作。取消不会扣费，满仓产物进入待领取区或在扣费前拒绝，并在界面说明。

### 7.3 解锁与任务

少量目标承担教学和中期指引：第一次成功撤离、带回第一份矿石、制作第一件装备、带回稀有种子、合作完成一次战斗、击败第二层首领。

任务记录完成条件、进度和奖励领取状态。已经拥有符合条件物品的旧档能按明示规则完成相关目标，不能要求销毁后重刷。消耗或上交材料的任务必须单独确认并准确扣物。

永久成长优先扩大选择：更多配方、容器空间、植物和设施。直接战斗数值提升保持有限，避免高级农场玩家让初始层失去挑战。

### 7.4 经济与失败后的再出发

为每种策略记录携带成本、消耗、带回价值、死亡损失、净收益和解锁进度。至少模拟基础装备、普通装备和高成本装备三种出发方式。

低成本出发也应有获取基础资源的机会，重装应提高生存或效率，但不保证获利。高层稀有资源应体现探索价值，农场产出提供稳定底线。

第一大阶段报告中，白菜收入相对原锚点偏高、育种速度随复制规模差异明显。本阶段先把装备消耗、制作和洞窟奖励纳入同一模型，再调农场与战备经济；不直接沿用“原来够宽裕就是平衡”的判断。

## 8. 功能设计：界面、声音、美术与教学

### 8.1 主要界面

必须具备农场洞窟入口、战备、制作、装备仓库、房间、地图、战斗、搜刮、撤离确认和回家结算十类界面。场景之间保留返回路径、当前局状态和可见错误提示。

重要信息用图标配文字；不只用颜色表达危险、可用或已准备。弹窗内显示操作结果，避免提示被遮罩压暗。支持项目当前窗口尺寸和常见 1080p，长物品名、满背包和双人面板都要真实检查。

出牌、拾取和结算过程中清晰显示等待状态，按钮避免重复提交；网络拒绝后的反馈保留在对应面板，不用瞬间消失的提示承担重要信息。

### 8.2 素材与表现

沿用现有低多边形农场风格。先用统一占位完成机制，再替换洞窟背景、入口、制作台、怪物、装备和资源素材。新增素材登记资产 ID、原件、运行时副本、用途和授权来源。

战斗优先保证目标、受击、格挡、治疗、状态变化和死亡可识别；不先制作复杂连续移动或长演出。卡牌和物品共享识别图标，减少玩家记忆成本。

声音包括基础 UI、出牌、受击、格挡、拾取、撤离、失败及农场／洞窟环境声；提供音乐和音效音量。动画速度可调或加速，长动画不能阻挡后续合法操作。

### 8.3 新手流程

保留原五步农场引导，新增可跳过、可重新查看的洞窟教学：选择基础装备 → 看物品牌 → 进行一次攻防 → 搜到货物并查看牌组变化 → 在撤离点回家 → 使用带回材料。

首轮使用受控节点和低风险敌人，避免随机图把教学步骤打散。教学奖励与普通奖励走同一结算逻辑，跳过或重放不重复发资源。

## 9. 联机、存档与恢复

### 9.1 房间与联网入口

首版支持创建／加入好友房间、昵称、版本检查、成员列表、准备状态、移除未出发成员和退出。局域网／本机双实例先用于技术测试，随后验证实际不同网络下的好友连接。

Godot 原生 ENet 可用于主机与客户端连接原型。互联网好友连接另行选择端口直连、平台组队或中继方案，记录实际需要的配置、可达性和服务依赖。若采用房间码，必须有对应的发现／连接服务，不能只做一个无法连接的界面号码。

第二大阶段交付必须至少实现并实测一种可供目标好友使用的连接方式；若仅通过局域网，应标记联机交付尚未完成。账号系统、云存档、公开匹配和主机迁移不作为本阶段必要功能。

### 9.2 状态裁定与同步

客户端提交意图，主机验证身份、所有权、当前节点／回合、费用和目标，再更新本局状态。客户端不自行生成奖励或决定伤害。

每次请求带动作 ID、局 ID 和所基于的状态版本；主机为已接受动作分配递增序号。重传同一动作返回已有结果，不再次扣费或领取；过期动作说明失效原因。重连以权威快照恢复，再接收后续事件。

随机数由本局裁定端生成，保存随机种子及推进状态或已生成结果；动画和界面不推进玩法随机。回放同一组有效动作应得到相同游戏状态。

联机采用好友信任下的主机权威原型，不能宣称能够阻止玩家修改自己的本地档或恶意主机作弊。规则校验仍覆盖正常误操作和网络重复请求。

### 9.3 带入与带出的事务

个人农场档、局中档和结算记录明确分离。带入物品标记为本局占用，不能同时在农场出售、制作或另开一局使用。

出发流程采用：生成局 ID → 写个人带入清单及占用状态 → 主机确认所有参与者资料 → 写本局初始快照 → 开始探索。中途失败时按记录恢复到出发前或已正式开始状态，不能靠猜测删物品。

撤离／死亡生成唯一结算 ID，记录每人的返还带入物、获得物、消耗与损失。个人档在同一次保存中应用结算并登记“已应用”；收到重复结算只回确认。主机记录各人确认状态，在未确认时保留可恢复的结果。

跨机器无法依靠一次文件写入实现真正的全局原子提交，因此以持久化清单、重试与幂等应用恢复。主机局档暂时不可达时，客户端保持未决状态和自己的凭据，提示联系原主机恢复；不自动返还完整带入装备同时保留已获得收益。

### 9.4 断线、退出与恢复规则

| 场景 | 原型处理 | 玩家看到的结果 |
| --- | --- | --- |
| 单人正常退出 | 保存当前局快照，下次恢复 | 可继续本局，或明确选择放弃 |
| 客户端掉线 | 暂停推进，等待重连；原型等待上限 120 秒可配置 | 显示等待者与剩余时间 |
| 客户端重连 | 校验身份和局 ID，发完整快照 | 恢复手牌、物品、回合与选择状态 |
| 等待超时 | 保存全局暂停状态，主机可结束会话，双方以后恢复 | 不凭掉线直接判定撤离或死亡 |
| 主机退出／崩溃 | 会话结束，原主机下次载入局档恢复 | 客户端保持物品占用，等待原局恢复 |
| 玩家主动放弃 | 明确展示损失，记录该玩家放弃结算；剩余玩家按人数规则继续 | 本人回家，损失规则与失败一致 |
| 主机个人放弃／全队放弃 | 个人放弃只结算本人并为剩余者维持会话；全队放弃需双方确认；结束会话则暂停 | 不把主机退出视为队友同意损失，详见 2.6、2.7 详细设计 |
| 结算时一端写盘失败 | 保留结果与未确认记录，允许重试 | 明确提示未完成，不能重复发物 |

重连使用稳定的本地玩家标识与会话凭据，不能只凭昵称认人。恢复要求同版本规则和原参与者匹配。首版不让新玩家在战斗中途替换旧成员。

### 9.5 旧档保护

当前代码的 `FarmGame.SAVE_VERSION` 为 5，实际存档路径为 `user://farm_save_v1.json`；旧文档中 version 1 的描述已经过时。

新增字段包括玩家标识、装备／材料库存、配方与目标解锁、配装、活动局引用、物品占用和已应用结算记录。采用明确版本迁移，保证旧金币、种子、批次、十块地的拥有状态、成长经验、市场锁定与育种机进度保留。

不把新增装备直接塞入原有作物批次。对未知版本或损坏局档提示恢复选项，不静默新建农场。主档、备份、临时文件的恢复路径覆盖个人档和局档；首次写入的可靠性也要验证。

## 10. 分期开发与交付

各子阶段完成自己的可玩入口、规则验证和交付报告后再进入下一阶段。必要依赖可提前做最小版本，但不能以“后面再接界面”为由交付只有后台函数的功能。

### 2.1 规则基线与工程基础

**状态：已完成（2026-10-01）。**交付报告：[archive/Godot_阶段2.1_交付报告.md](./archive/Godot_阶段2.1_交付报告.md)。

**功能：**建立物品、卡牌、玩家战斗状态和本局状态的定义；记录原型规则版本；增设战备／洞窟入口的占位；为个人库存新增可迁移结构，建立动作校验、事件结果和局存储边界。

**开发重点：**拆开已有农场与新增探险责任，复用原有种子、金币和保存入口；避免把所有战斗继续堆进 `farm_game.gd`。定义唯一实例 ID、局 ID、动作 ID和结算 ID。

**交付：**规则基线表、数据示例、旧档迁移、可进入的战备界面、初步网络技术试验记录。

**验收：**真实 v5 旧档加载后原有资产一致；新增系统可以打开退出；同一物品不能同时属于两个位置；原农场八项回归保持通过。互联网连接可行性开始验证，发现服务依赖及时记录。

### 2.2 单人卡牌战斗原型

**状态：已完成（2026-10-01）。**交付报告：[archive/Godot_阶段2.2_交付报告.md](./archive/Godot_阶段2.2_交付报告.md)。

**功能：**固定起始配装、一场战斗、基本卡牌、能量抽牌、格挡与状态、敌人意图、胜利和失败、战斗日志。

**建议内容：**8～12 种牌效果模板、3 种普通敌人行为，足以测试攻击、防御、恢复和负担；这是内容预算，不是完整版本承诺。

**交付：**可以反复进入的单人战斗、固定种子算例、目标和状态说明、胜负画面。

**验收：**不看开发文档能完成一场战斗；费用不足和目标死亡不误扣；空抽牌堆可正确洗牌；状态与日志可核对；保存恢复不改变手牌或敌人意图。

### 2.3 格子背包、物品生成牌组与搜刮

**功能：**三种容器、放置旋转、牌组预览、延后加入牌库、物品拾取丢弃、消耗品实体扣除、连续两场战斗。

**建议内容：**12～16 种物品，覆盖武器、防具、补给、材料、种子和货物；包含至少两种“值钱但影响战斗”的货物。

**交付：**从战备进入战斗、搜到物品、整理后打第二场的可玩流程。

**验收：**物品占格与牌实例数量可核对；三个容器加入时点正确且不重复；拾取在下一战生效；满包不吞物；药水多张来源牌不能多次消耗同一份实体；存读档保持布局和归属。

### 2.4 单人洞窟与撤离闭环

**功能：**一层分支地图、战斗与宝箱／事件／休整节点、至少两个撤离抉择、深入目标、死亡保护、出发占用与回家结算。

**交付：**农场出发 → 探索 → 搜刮 → 撤离／死亡 → 回家；节点存档和结算报告。

**验收：**提前撤离也得到合法收益；死亡只保留允许保护的物品；重复回家不重复发装备；关闭重启恢复同一地图和奖励；满仓可安全结束本局；强制关闭发生在出发与结算中间仍可恢复。

**试玩关口 A：**实际分别尝试轻装、带货继续深入和满载撤离。若玩家不关心搜到什么或何时撤离，优先调整物品与战斗，不扩层数。

### 2.5 农场衔接、制作与成长

**功能：**装备／材料仓库、制作台、补给配方、战备设施升级、至少一种完整可种的新植物、成长看板和目标奖励。

**建议内容：**6～8 个配方、3 类设施升级、6 个教学／成长目标；稀有种子至少有一个实际可验证的独特用途。

**交付：**带回材料制作装备、带回种子种植、出售货物再准备出发的三条成长链，以及经济模拟报告。

**验收：**新种子能购买／获取、播种、照料、育种和出售；制作和奖励领取不重复扣发；失败后可以低成本再出发；农场时间在探险期间正常推进；新旧资源没有可重复套利路径。

### 2.6 双人合作与跨端结算

**功能：**房间与准备、双人战斗、共同路线确认、个人／公共奖励、分享、倒地救援、共同撤离、主机裁定、两端各回自己的农场。

**交付：**本机双实例测试、两台设备测试、一种实测可达的好友连接方式、双人完整探险。

**验收：**玩家不能操作队友牌或物品；同时出牌和同时拾取只按权威顺序结算；分享取消不丢物；双方看到相同敌人与节点；结算分别回正确个人档，主机不代替客户端直接写农场文件。

**试玩关口 B：**验证保护队友、分享救命物资和共同撤离有实际意义；记录每局等待时间、路线分歧和公共物资分配体验。

### 2.7 重连、持久化与异常恢复

**功能：**局快照、动作去重、重连凭据、暂停恢复、主机关闭后恢复、未确认结算重发、保存失败提示和备份恢复。

**交付：**故障矩阵、可重复的恢复测试、单人及双人恢复操作说明。

**验收：**在出牌、拾取、分享、出发扣物、撤离、死亡结算和个人写盘前后分别断线／强退；恢复后状态一致，不复制物品、不重抽奖励、不误返还装备。主机不可达时明确保留未决状态；不能把无法恢复的情况宣称已解决。

### 2.8 第二层内容、表现与新手体验

**功能：**第二层、精英与首领、层间奖励梯度、任务引导、正式图标与主要模型、基础音效、快捷信号、清晰结算和窗口适配。

**整体建议内容预算：**累计 24～32 种物品、18～24 种牌效果模板、6～8 种普通敌人、2 种精英、1 个首领、6～8 个事件、2 种稀有植物。优先复用已有牌效果组合；效果模板数与牌实例数不是同一口径。

**交付：**两层单人／双人完整版本、可跳过新手教学、素材清单和关键界面预览。

**验收：**新玩家能理解物品如何影响牌组、保护区和死亡损失；两层收益和风险有区别；教学可重复查看但奖励只发一次；双人满包、长名称和较小窗口下仍能操作；模型和动画不影响规则时序。

### 2.9 全量回归、平衡与 Windows 交付

**功能：**完成全流程回归、旧档兼容、经济与战斗模拟、真实网络试玩、导出发布构建、操作说明和已知限制。

**交付：**第二大阶段交付报告、Windows 可运行包、源工程、数据表、素材清单、测试结果、连接／恢复指南、未解决问题列表。

**验收：**新档和 v5 旧档各完整玩单人；两台设备完成双人；实测掉线重连、主机退出恢复、满仓结算、死亡后再出发；导出包与编辑器行为一致，发布构建关闭调试发物和时间推进。

只有全部必要功能及恢复路径通过，第二大阶段才标记完成。内容数量可以基于试玩调整，但不能通过删掉合作、撤离或农场衔接来宣称完成本阶段。

## 11. 工程划分建议

以下是建议结构，不要求为了符合目录机械搬动所有旧代码。

| 模块 | 责任 | 建议位置 |
| --- | --- | --- |
| 农场规则 | 原有种植、育种、市场、升级 | `scripts/domain/farm_game.gd` 及现有定义 |
| 物品定义 | 尺寸、卡牌、用途、保护规则和价值 | `scripts/domain/item_defs.gd` |
| 卡牌定义 | 费用、目标、效果和状态定义 | `scripts/domain/card_defs.gd` |
| 战斗规则 | 回合、出牌验证、效果和敌人行为 | `scripts/domain/combat_game.gd` |
| 探险规则 | 地图、节点、搜刮、撤离、失败 | `scripts/domain/expedition_game.gd` |
| 物品与制作 | 归属、布局、占用、配方与库存事务 | `scripts/domain/inventory_game.gd` 等 |
| 本局存储 | 快照、日志、结算、恢复 | `scripts/services/expedition_store.gd` |
| 联机 | 连接、请求校验、序列、快照与重连 | `scripts/services/session_host.gd` 等 |
| 场景与界面 | 战备、地图、战斗、搜刮、房间、结算 | `scenes/`、`scripts/ui/`、`scripts/world/` |
| 配置与素材 | 可调数据及运行时资产 | `data/`、`assets/` |

规则层接收命令，返回成功／拒绝原因、状态变更和表现事件。单人也使用同一规则命令入口；网络只是把命令传给裁定端，不维护另一套算法。

避免过早拆成多套微服务或设计通用技能编辑器；首先让表驱动定义和少量可组合效果覆盖当前内容。新增节点明确命名，RPC 节点路径保持双方一致，不用宽泛 `get_children()` 猜身份。

## 12. 验证、平衡与试玩记录

### 12.1 必须覆盖的规则验证

- 背包：旋转、重叠、越界、非法容器、自动整理、来源物品删除后关联牌清理。
- 战斗：能量、抽弃牌、延迟加入、持续状态、倒地救援、同时击杀、两人同时出牌、胜负边界。
- 探索：地图连通、节点只能完成一次、奖励固定、层间状态保留、撤离与失败。
- 库存：满包、满仓、分享与取消、制作扣料、任务上交、出发占用、带入返还和新物品获得。
- 存档：v5 迁移、主备损坏、写入失败、活动局恢复、重复结算和旧版本拒绝提示。
- 联机：版本不同、身份错误、重复／过期动作、同时领取、掉线、重连、主机退出和离线收结算。
- 农场：原八项回归、新植物的照料与育种、探险期间离线成熟和北京时间跨日刷新。

测试档与玩家档隔离，不能靠删除真实 `user://` 目录开始测试。固定时间和随机种子由测试注入，不修改 Windows 系统时钟。

### 12.2 试玩与数值口径

单人和双人分别记录新手首局、低成本局、普通装备局、高成本局以及失败后恢复局。关键数据包括单局时长、每场回合数、胜率、生命消耗、实际带回价值、失败损失、牌组大小、货物牌比例、撤离选择和配方解锁所需局数。

初步体验目标：第一局可获得明确收获；早期普通撤离约 1～3 次可推进一个基础制作目标；更深层提供独特资源；失败后无需等很久种菜才能重新游玩。这些是待验证目标，不是事先保证的数值结论。

特别检查“把所有物品都塞满”“只带最小武器”“所有稀有物都放保险箱”“放弃后刷免费装”“反复重连拿奖励”等策略是否成为唯一最优或套利方式。

### 12.3 实机与导出

每个涉及界面的子阶段在真实窗口完成一次试玩，不用规则测试替代。worktree 首次运行前先执行 Godot 编辑器导入，`--path` 指向包含 `project.godot` 的当前工程。

在 2.6 后使用两台设备验收，并覆盖不同网络连接。2.9 使用发布导出包再跑完整流程；记录实际机器、连接方式、存档版本和结果，未做的检查写“未验证”。

## 13. 依赖、优先级与范围控制

主要依赖为：**2.1 → 2.2 → 2.3 → 2.4 → 2.5 → 2.6 → 2.7 → 2.8 → 2.9**。网络可达性在 2.1 提前试验，存档幂等从出发结算开始实施，不能等 2.7 才补；2.7 负责扩全故障覆盖。

必须优先解决的风险是物品入牌后的战斗手感、撤离选择是否成立、合作等待与沟通、跨端物品结算以及互联网好友连接。美术数量、事件数量和四层内容排在这些问题之后。

计划不预设没有依据的固定完成日期。每个子阶段拆任务书时，根据实际规则复杂度、素材缺口和联机服务方案估算工时，并以可玩交付物为进度依据。

若需要缩小范围，先缩物品和敌人数量、事件分支、装饰表现；保持单人／双人、搜刮改变牌组、撤离风险和农场用途完整。试玩关口不通过时，回到对应机制调整，不用新增内容掩盖问题。

## 14. 待试玩或技术验证后确定的事项

| 事项 | 本计划暂用方案 | 最晚确定节点 |
| --- | --- | --- |
| 占格数与卡牌数量是否严格一致 | 普通物品严格对应，消耗品共享实体次数 | 2.3 结束 |

| 倒地救援与战后恢复 | 有限救援，胜利后低生命恢复 | 2.6 试玩关口 B |
| 个人撤离 | 首版共同撤离 | 2.6 试玩关口 B |
| 单局与层数 | 两层约 20～35 分钟 | 2.8 结束 |
| 好友互联网连接方式 | 原生直连验证后选平台或中继等实际方案 | 2.6 开始前 |
| 免费基础装备条件 | 保证再出发，避免可出售套利 | 2.5 结束 |
| 新植物名称、形象与配方 | 按实际素材与玩法配套决定 | 2.5 开始前 |

## 15. 参考调研与本项目采用方式

- [Mega Crit：《杀戮尖塔 2》合作模式介绍](https://www.megacrit.com/news/2026-03-05-early-access-launch/)说明了好友合作、多人专用牌和队伍配合。本项目借鉴共同战斗的设计方向，物品分配和撤离按自身规则原型验证。

- [Farm Together 2 官方商店页](https://store.steampowered.com/app/2418520/Farm_Together_2/)作为农场经营体验参考。现有农场的现实时间成长保留，用主动探险补充等待期间的可玩内容。
- [Godot 4.6 高层多人文档](https://docs.godotengine.org/en/4.6/tutorials/networking/high_level_multiplayer.html)提供 ENet、RPC、连接与断开等技术依据，并说明跨互联网的主机可达性要求。本文的状态去重、物品结算和恢复方案是本项目工程设计，不是引擎自动保证的功能。

参考游戏提供机制依据，本文中的具体容量、回合、层数、奖励、恢复流程和交付顺序均为本项目的计划或原型建议。
